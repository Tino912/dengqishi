## 踩过的坑（重要，别重复踩）

1. **`/tmp` 只有 10MB tmpfs** → Chrome 的 profile 写不下就 SIGTRAP/SIGSEGV 崩溃。
   表现是"同样的命令时好时坏"，很难查。**修复：profile 与临时文件全部放 `$HOME/.cache`。**
   这一条同时解决了 `--screenshot` 一直失败的问题。
2. **`--virtual-time-budget` 在本机必崩**。改用"页面内同步推进游戏循环"，
   让 `--dump-dom` 在加载完成时直接拿到结果。
3. 本地回环必须 `unset HTTP_PROXY HTTPS_PROXY`，否则 curl/chrome 访问 127.0.0.1 报 502。
4. 后台 `&` 启动的 Chrome 会被沙箱打断；要在**同一条命令内**完成启动→操作→收尾。
5. TS 的 `private` 只是编译期，运行时照常可访问 —— 验证脚本正是靠这点读 `renderer.lights`。

## 验证体系（两层）

- **逻辑层 `npm run sim`**：Node 里跑真实游戏逻辑 + 种子随机可复现。
  → 曾抓到致命 bug：波次清理判断写在 `if (w.spawned) continue;` **之后**，
  导致已清波次永不标记 cleared，**Boss 永远不出现**。`tsc`/`build` 都查不出这类问题。
  修法：先 `if (!w.spawned) { 触发 }`，再 `if (w.spawned && !w.cleared) { 判定 }`。
- **渲染层 `npm run verify`**：真实无头 Chrome 跑构建产物，页面自采样 `getImageData`
  + DOM 状态，逐关检查。当前 9 项全绿、0 JS 报错。
  光照实测：玩家处亮度 204/235/91，四角仅 7~27 → 黑暗光照确实生效。

## 注意

- 我的一个自动化检查曾误报"黑暗光照失效"，实际是**测错了位置**：
  相机被关卡边界钳制，玩家在屏幕 (300,315) 而非画布中心 (640,288)。
  → 教训：断言要针对"玩家实际所在位置"，不要假设玩家在画布正中。
