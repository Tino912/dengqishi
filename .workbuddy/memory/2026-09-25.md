# 新一轮：夜色提亮 · 起步攻击范围 · 迷雾（357 → 358 断言）

用户原话三句：**「适当提升角色初始的攻击范围」+「适当提升地图亮度，使地图可见但类似于晚上」
+「给地图添加迷雾，灯照的地方迷雾会散去」**。三件事互相独立，分开验。

### 做了什么
1. **起步攻击范围 ×1.20**：`world.gd` 的 `const BASE_REACH := 1.20`（刀锋 66 → 79.2），
   `reach_mul()` 用**加法**（`BASE_REACH + 恩赐×0.12 + 词条×0.12`）—— 用乘法会把已有的
   "+0.12/级" 断言搞失真。**补两条绝对断言**（`==1.20`、`swing_reach()==79.2`），
   因为这一段原来**一条绝对值都没有**，整片"比基准多多少"在 `BASE_REACH` 退回 1.0 时全绿。
   顺带修真实回归：机器人试玩的交手距离原本写死 62/64/44，改成从 `swing_reach()` 推
   （`press_in=rch*0.78` / `atk_at=rch*0.95`）—— 写死的话它永远贴到 60px 才出手，
   **不会用远程武器**，表现为"时而清完三波、时而只清一波"。
2. **夜色**：`light_rig.gd` 的 `NIGHT_MIN(0.42,0.46,0.60)` / `NIGHT_SPAN 0.115` /
   `NIGHT_BASE 0.018`，`t = clamp((1-ambient-BASE)/SPAN)`，`cm.color = NIGHT_MIN.lerp(white,t)`。
   **旧区间是坏的**：三关 `ambient` 0.90/0.955/0.975 落点全在 `t=0` → 永远最暗、图纯黑，
   那个"一关更比一关黑"的旋钮**实际拧不动**。同时把三关调色板提亮（**色相没动**，只抬明度）
   并给每关加 `"mist"` 色（L1 `#464f6b` / L2 `#4a4166` / L3 `#3d5559`）。
3. **迷雾 `src/fog.gd`（新文件）**：**不能用 Light2D** —— 2D 光照只能加，`BLEND_MODE_SUB`
   减的是 RGB 不是 alpha，做不出"擦掉雾"。自己算：屏幕切 **80×45** 格 → 逐格算"被照亮多少"
   → 80×45 贴图 → 全屏着色器（读 `SCREEN_UV`）画雾 + **三层倍频噪声**絮。
   视线用**射线扇**（192 条/盏 × `Proj.ray_rect_dist` slab 法，`WALL_PAD 10`）。
   在 `World.step()` 里调，每 0.05s 重建；雾絮相位取自 `world.time` → 漂动**也可复现**。
   `KIND_SCALE` 给每类灯开雾半径系数（玩家 0.82），`OPENER_MAX=10`，`MIST_MAX=0.40`。
   清关走 `World.tick_fx` 的 `disperse()/reset_fade()/tick_fade()`
   （**tick_fx 在世界冻结时也跑**，所以面板期间雾照样在散/回填）。

### 本轮踩的坑（已写进 README 二.14.6，共 5 条）
1. **迷雾的坐标系与灯光层不是同一个**（真 bug）。`LightRig`/`Bloom` 的 `position` 是
   `Proj.cam_offset(...)`（局部空间是"世界投影过来的"），迷雾**照抄了这句**，
   但它是**屏幕空间** → 整块矩形被搬出屏幕，**只盖住 ~53%**，还是照亮场的错位切片。
   不报错、不抛异常，只是"看起来有点怪"。
   **发现方式（可复用）**：把 `fog_on` / `fog_off` 两张截图**相减，打一张 ASCII 亮度图** ——
   增量只在屏幕上半部分有值、一条水平硬边横在第 400 行，一眼看出是矩形画歪了。
2. **屏幕空间的滞后状态不能跨相机移动来比**。验"雾会回填"时第一版把玩家 `teleport` 走，
   `reveal` 直接读 0（其实是"另一格的历史"）。→ 改成**不搬相机**：让连击掉光、
   半径自己缩回（620 → 150），那个点就出了灯范围。
3. **整体提亮会让逐像素差异断言退化成恒真**。三图差异原来比"多少像素不一样"（阈值 25%），
   提亮后**任何两张图都 ~99% 差异** → 恒真。→ `_diff_ratio_norm`：**先各自减掉自己那块的
   平均色**再比，消掉"整体明暗/统一色偏"这个自由度。实测三图 88.1/93.2/97.6%，
   "同关重建两次"两种度量都 **0.00%**。（写它时自己踩了一下：第二趟忘了跳过越界占位符，
   "有效差异数"超过"有效对数"，吐出 101.6% —— **这类指标要能自证**。）
4. **雾的浓淡是拿眼睛调的**。第一版 `MIST_MAX = 0.58`，断言全绿（"雾让画面变亮 0.053"），
   但人眼看过去没照亮处被压成**一整块灰板**，地砖缝、墙轮廓全糊掉 —— 而用户要的是"地图可见"。
   → 降到 **0.40**，噪声从两层加到三层。**数字全绿 ≠ 观感对，必须把两版截图并排看。**
   事后用 PIL 补了量化（`21-fog-off` vs `02-level1-start`，同一块没有 HUD / 没有玩家光晕的地面）：
   均值 **42.5 → 62.2（+46%）**，而局部对比度（与 8px 均值滤波之差的标准差）**3.90 → 2.78（−29%）**
   —— 雾是"**提亮但压平**"：地更亮、地砖缝更糊。对大目标（"地图可见"）净效果仍是正的
   （提亮前那块只有 42/255，绑定约束是亮度而非对比度），但 `MIST_MAX` 是**权衡**，
   只看"全屏均值涨了"会得出"雾越多越好"的错结论。
5. **一条"没牙"的断言是靠变异测试才暴露的**（本轮唯一一次变异不符合预期）。"夜色"原来只有
   `mean > 0.05 / < 0.45`；变异 `夜色永远压到最暗一档`（把 `t` 写死 0）跑出 **0 条变红**。
   不是补丁打歪，是**命题问错了问题**：提亮之后最暗一档也只是暗掉一半，照样落在区间里
   （那两条防的是提亮前底色 0.008 的年代）。→ 补一条**只拧一个变量**的对照：同一帧、
   同一世界，把 `world.ambient` 拧到 0.98（`d=0.02 → t≈0`），全屏均值必须明显下降
   （实测 **0.2121 → 0.1732**，差 0.039 > 0.02）。357 → **358**。
   **教训**：断言没红先分清"补丁没打在生效层"（上轮遇到）还是"断言问错了问题"（本轮遇到）；
   后者要**让旋钮转一下**（单变量前后对照），**不是把阈值调松**。

# 追加：用户要「迷雾最浓」→ `MIST_MAX` 0.40 → **1.0**

用户一句「帮我把迷雾改成最浓」。着色器上限就是 1.0，所以取满格。代价量清楚了
（同一块无 HUD / 无玩家光晕的地面，PIL 量）：关雾 **42.5 / 3.90** → 雾 0.40 **62.2 / 2.78**
→ 雾 1.0 **91.2 / 2.21**（均值 **+115%**、局部对比度 **−43%**）。
**灯照不到的地方地形基本看不见了**，屏幕上只剩灯照的那一圈是清的 —— 这是"最浓"的定义使然。
折中点 0.55~0.65（想"浓但还看得见地形"就用它）。

### 拉满之后立刻踩到的第二个坑（重要，可复用）
"夜色旋钮"那条断言（上一轮刚补的）**马上红了**：雾变不透明后，全屏均值由雾决定，
把地图压暗屏幕几乎不动 —— 实测 `0.2925 → 0.2839`，**只差 0.0086**，卡在 0.02 的阈值下。
差一点又去调阈值（正是要避免的修法）。正解是**关雾再量**：量哪一层就把别层冻住
（雾关掉后 `0.1580 → 0.0986`，差 0.059，判据立住）。雾开着那个 0.0086 不删，
改成**只记进报告不断言**的样本 `night_delta_fog_on` —— 它说明的是真事：
**雾拉满后夜色在观感上已被雾盖住**，这是"最浓"的必然结果，不是缺陷。

这跟上一轮"底色提亮 → 比值断言测的是底色"是**同一类错误**（判据被另一层主导），
所以又写进 `MEMORY.md` 硬约定第 7 条：**量哪一层，就把别层冻住。**
