### 全量 32 个变异跑完之后又挖出来的东西（比预想的重要）
一条断言里同时藏了三个错、互相掩护 —— `★ 走路的两个反相相位在屏幕上确实不一样`：
1. 「反相两帧」**取错帧**：写的是第 0 与第 4 帧，但 `hip = sin(ph)*AMP`
   在这两个相位**都是 0**（两条腿都停在中立位，画出来一模一样）；
   真正的反相极端是相位 π/2 与 3π/2（第 2 与第 6 帧）。
2. 于是它量到的其实是 sway 与 cloak，跟腿没关系。
3. 采样窗还开得太大（y ≥ −26），把斗篷下摆与躯干底都框进来了。

三个错互相掩护，所以症状自相矛盾：**"把腿冻住"的变异打不红它**（看着像它在盯腿），
而**"把地图压暗"的无关变异能打红它**（看着像亮度问题）。
三处一起修（真反相帧 + 窗收窄到 y ≥ −12 + 按亮度归一化）之后：
归一化差 0.0101 → **0.0861**，新变异"腿不再跟着姿态画"**能打红了**，
两条无关变异的连带也消失（夜色 2 条红 → 1 条）。

**教训三条**：① 断言红得莫名时先查它到底在量什么（取错帧会让断言恒真/恒假）；
② **采样区只装你要盯的那一层**；③ 绝对像素差只在"两次同一光照"时可比。

## 本轮：挥击范围线 == 实际判定 · 伤害数字放大分级

用户原话：「发现一些武器实际攻击范围与标出来的线不符，请修复。
另外请放大攻击时伤害数字显示。」

### 根因：同一次挥击有两套几何
- 判定读 `w["arc"]`；画线把角度**写死 0.9 rad**、射程还多乘一个 **0.9**。
- 结果只有 `arc` 恰好 = 0.9 的武器对得上 → **长枪画宽 45%、镰刀画窄 67%**，
  弩（`shot`，没有近战扇形）**也画了一条**出来。用户看到的"线不符"就是这个。

### 修法
- `World.swing_cone()` 成为**唯一真源**：形状 = 半径 40 的实心圆 ∪ 40 → r 的扇形
  （"钥匙孔"）。判定 `cone_hits()` 与画线 `cone_polygon()` **都从它派生**。
- 几何挂在 `player.swing_cone`（普攻 1.0 / 连击 0.9 射程不同，得跟着这一次挥击走）。
- `has_swing_sector(w)` 取代散落的 `style == "shot"` 判断。
- `World.swing_guide_only` 开关：只画范围线、不画刀光，专供像素测试。
- 伤害数字：`Art.TEXT_SIZE` 字号表（hit 22 / crit 28 / dot 16 …），`_add_text` 加
  `txt_key`；描边随字号缩放；**发光从"字号≥17"改成显式键表** `TEXT_GLOW_KEYS`
  （`["crit","hurt"]`）—— 否则一放大就全场发光。

## 第四条记录：尺寸断言"没牙"的根因（当天第二次，取代上一条的收尾数字）
