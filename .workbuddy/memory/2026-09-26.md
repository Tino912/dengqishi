### 做了什么
- 新增 `godot-lightknight/src/pose.gd`（`class_name Pose`，270 行 static 纯函数）：
  把"姿态"从"绘制"里抽出来。走路 / 挥击 / 施法三类姿态求解。

  头盔面罩 + 两点眼光、**武器绕手转**（`_draw_weapon` 进武器局部空间，`grip` 逐武器不同）。
  所有部位走唯一坐标入口 `_bx()`。回身类技能改用**镜像翻转**。

  写这两个字段、`tick` 里递减；顺手把重绘封成 `World.mark_redraw()`。

  + 新工具 `_region_moved()`（动了的占比）、`_region_diff_norm()`（按亮度归一化）。
  基线 **390/390**，两次 `report.json` 逐字节相同（md5 `bf6d237cfad4df61f33da242c45808d4`）。
- `tools/godot-mutate.py` 25 → **32 个变异**，新增 7 个针对姿态动画的。

### 本轮最大的收获（已写进 DETAIL 与 README 15.9）
**一条断言被两个独立的层各能单独满足 → 它就是个没牙的烟测。**
`★ 挥击的前摇与挥出画出来不一样` 在"把艺术层武器冻住"之后**照样绿**：
① `sw["lean"]` 带着躯干/头/斗篷一起动；② `world.gd` 那道跟着 `attack_t` 扫的
刀光弧 + 月牙斩落在同一个窗里。修法是**让旋钮转一下**（补 `p.attack_alt` 单变量对照），
不是调阈值；原断言改措辞 + 在变异表里列 `forbid` 并注明"应该保持绿"。

附带教训：**`_region_diff` 的均值会被"窗里有多少空地"稀释** —— 武器是细线，
在 156×96 窗里只占 1~2%，"只翻挥向"这一对均值只有 0.0094（卡在 0.02 下），
它确实动了只是动的地方少 → 加"动了的采样点占比"（武器区 0.1696 / 两个对照均为 0）。
配对照时踩了两次：先把"重取"写成**同一张图自己比自己**（恒 0，什么都没验），
又选了块被武器切掉一角的"腿部区"（假阳性 0.1024）。定位还是靠**两帧相减打变化图**。

### 当前的“没红”排查结论（留给下次）
变异"没红"必须先分清：**补丁没打在生效的那一层** vs **断言问错了问题**。
本轮两次都是后者，而且第二次是"有第二个层在同一件事上提供了信号"这种新形态。

### 全量 32 个变异跑完之后又挖出来的东西（比预想的重要）
一条断言里同时藏了三个错、互相掩护 —— `★ 走路的两个反相相位在屏幕上确实不一样`：
1. 「反相两帧」**取错帧**：写的是第 0 与第 4 帧，但 `hip = sin(ph)*AMP`
   在这两个相位**都是 0**（两条腿都停在中立位，画出来一模一样）；
   真正的反相极端是相位 π/2 与 3π/2（第 2 与第 6 帧）。
2. 于是它量到的其实是 sway 与 cloak，跟腿没关系。
3. 采样窗还开得太大（y ≥ −26），把斗篷下摆与躯干底都框进来了。

三个错互相掩护，所以症状自相矛盾：**"把腿冻住"的变异打不红它**（看着像它在盯腿），
而**"把地图压暗"的无关变异能打红它**（看着像亮度问题）。
三处一起修（真反相帧 + 窗收窄到 y ≥ −12 + 按亮度归一化）之后：
归一化差 0.0101 → **0.0861**，新变异"腿不再跟着姿态画"**能打红了**，
两条无关变异的连带也消失（夜色 2 条红 → 1 条）。

**教训三条**：① 断言红得莫名时先查它到底在量什么（取错帧会让断言恒真/恒假）；
② **采样区只装你要盯的那一层**；③ 绝对像素差只在"两次同一光照"时可比。

## 本轮：挥击范围线 == 实际判定 · 伤害数字放大分级

用户原话：「发现一些武器实际攻击范围与标出来的线不符，请修复。
另外请放大攻击时伤害数字显示。」

### 根因：同一次挥击有两套几何
- 判定读 `w["arc"]`；画线把角度**写死 0.9 rad**、射程还多乘一个 **0.9**。
- 结果只有 `arc` 恰好 = 0.9 的武器对得上 → **长枪画宽 45%、镰刀画窄 67%**，
  弩（`shot`，没有近战扇形）**也画了一条**出来。用户看到的"线不符"就是这个。

### 修法
- `World.swing_cone()` 成为**唯一真源**：形状 = 半径 40 的实心圆 ∪ 40 → r 的扇形
  （"钥匙孔"）。判定 `cone_hits()` 与画线 `cone_polygon()` **都从它派生**。
- 几何挂在 `player.swing_cone`（普攻 1.0 / 连击 0.9 射程不同，得跟着这一次挥击走）。
- `has_swing_sector(w)` 取代散落的 `style == "shot"` 判断。
- `World.swing_guide_only` 开关：只画范围线、不画刀光，专供像素测试。
- 伤害数字：`Art.TEXT_SIZE` 字号表（hit 22 / crit 28 / dot 16 …），`_add_text` 加
  `txt_key`；描边随字号缩放；**发光从"字号≥17"改成显式键表** `TEXT_GLOW_KEYS`
  （`["crit","hurt"]`）—— 否则一放大就全场发光。

### 自检新增 25 条（413/413）
- `_section_swing_cone()` 19 条：8 把武器 × 扇形内外 **5040 个点**，
  `cone_hits` 与 `Geometry2D.is_point_in_polygon` **零分歧**；像素带沿地面坐标取样
  （外圈 0.0859 / 圈外 0.0000 / 内圆 0.1563 / 重取帧 0.0000）；端到端确认
  `player_swing` 真的写了 `swing_cone`（普攻 r=124.8；连击 112.32 = 恰好 0.9×）。
- `_section_text_readability()` 6 条：表里阈值 + 发光键表 + 渲染影响（亮像素
  644 → 1130，×1.75）。
- `tools/godot-mutate.py` 32 → **40 个变异**（8 个针对本轮）。

### 本轮踩的坑（已写进 DETAIL / MEMORY / skill）
1. **"看得出来"的判据用均值会被窗里的空地稀释 → 看着像"旋钮失灵"**：
   同一个开关，600×420 的窗上均值只有 0.0056（阈值 0.01 → 判红），
   换 `_region_moved` 占比 + 400×280 小窗 → 4.63%。
   **两种窗反着用**："精确为 0" 用大窗，"看得出来" 用小窗。
2. **沙箱批量删除保护是按 turn 累计的，被拦时卡住等确认而不是报错退出**：
   脚本里 `rm -rf shots`（60 个文件）→ 自检 3 分钟无输出、`ps` 里连 godot 都没有。
   实测：一条命令里删 30+30 被拦（累计 60 > 50）；覆盖式**写** 60 个不拦。
   → 脚本改**只写不删**（`find -newermt` 只读地列多余文件）。
3. **GDScript 解析错误会让 Godot 挂住不退出**：`Parse Error: Identifier "d_sc" not
   declared`（我删了声明却还在引用），外面只看到"这轮自检好慢"。
   → `timeout 400` 收到 **200**，并先 grep `SCRIPT ERROR|Parse Error` 再怀疑性能。
4. **"同一个判断在 N 处各写一遍 → 迟早漏一处"**：修法是收成一个总闸 + 留变异锚点，
   不是给漏掉那处补一个 if。
