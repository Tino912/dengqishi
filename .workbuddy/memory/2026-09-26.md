以及给主角一个更好看的外形以及流畅的动画，如走路，施放武器技能等。」

### 本轮最大的收获（已写进 DETAIL 与 README 15.9）
**一条断言被两个独立的层各能单独满足 → 它就是个没牙的烟测。**
`★ 挥击的前摇与挥出画出来不一样` 在"把艺术层武器冻住"之后**照样绿**：
① `sw["lean"]` 带着躯干/头/斗篷一起动；② `world.gd` 那道跟着 `attack_t` 扫的
刀光弧 + 月牙斩落在同一个窗里。修法是**让旋钮转一下**（补 `p.attack_alt` 单变量对照），
不是调阈值；原断言改措辞 + 在变异表里列 `forbid` 并注明"应该保持绿"。

附带教训：**`_region_diff` 的均值会被"窗里有多少空地"稀释** —— 武器是细线，
在 156×96 窗里只占 1~2%，"只翻挥向"这一对均值只有 0.0094（卡在 0.02 下），
它确实动了只是动的地方少 → 加"动了的采样点占比"（武器区 0.1696 / 两个对照均为 0）。
配对照时踩了两次：先把"重取"写成**同一张图自己比自己**（恒 0，什么都没验），
又选了块被武器切掉一角的"腿部区"（假阳性 0.1024）。定位还是靠**两帧相减打变化图**。

### 当前的“没红”排查结论（留给下次）
变异"没红"必须先分清：**补丁没打在生效的那一层** vs **断言问错了问题**。
本轮两次都是后者，而且第二次是"有第二个层在同一件事上提供了信号"这种新形态。

### 全量 32 个变异跑完之后又挖出来的东西（比预想的重要）
一条断言里同时藏了三个错、互相掩护 —— `★ 走路的两个反相相位在屏幕上确实不一样`：
1. 「反相两帧」**取错帧**：写的是第 0 与第 4 帧，但 `hip = sin(ph)*AMP`
   在这两个相位**都是 0**（两条腿都停在中立位，画出来一模一样）；
   真正的反相极端是相位 π/2 与 3π/2（第 2 与第 6 帧）。
2. 于是它量到的其实是 sway 与 cloak，跟腿没关系。
3. 采样窗还开得太大（y ≥ −26），把斗篷下摆与躯干底都框进来了。

三个错互相掩护，所以症状自相矛盾：**"把腿冻住"的变异打不红它**（看着像它在盯腿），
而**"把地图压暗"的无关变异能打红它**（看着像亮度问题）。
三处一起修（真反相帧 + 窗收窄到 y ≥ −12 + 按亮度归一化）之后：
归一化差 0.0101 → **0.0861**，新变异"腿不再跟着姿态画"**能打红了**，
两条无关变异的连带也消失（夜色 2 条红 → 1 条）。

**教训三条**：① 断言红得莫名时先查它到底在量什么（取错帧会让断言恒真/恒假）；
② **采样区只装你要盯的那一层**；③ 绝对像素差只在"两次同一光照"时可比。
