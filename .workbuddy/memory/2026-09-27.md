## 1. 雾锚定（`fog.gd`）
- 旧：噪声采样 `SCREEN_UV × mist_scale` = **贴在屏幕上** → 主角一走整片雾跟着镜头平移。
- 新：`gw = (SCREEN_UV.x*view_w − view_w/2 + cam.x,
  (SCREEN_UV.y*view_h − view_h/2)/ysquash + cam.y + hz/ysquash)`；三个新 uniform
  `cam_xy` / `view_w` / `ysquash`，`sync()` **每步**重发 `cam_xy`。投影是仿射的 → 反解精确。
- ⚠️ 屏幕雾胞横竖不等（横向 55px、纵向被 y 压 0.62）→ 世界坐标里 y 要**除以 ysquash**。
- 自检 ②f：相机平移 83px，只比**同一帧内 `开雾 − 关雾`** 这一层。
  **正 0.0013 / 反 0.0250 = 19×**；对照图 `shots/26-fog-anchor.png`（3 格）。
- ⚠️ **比整帧是不行的**：抗锯齿在屏幕空间，平移过的画面永远不可能逐字节相同
  （地形差 0.0029，比"正"那条的 0.0013 还大 —— 拿它当判据必然误判）。

## 2. 伤害光圈（`art.gd` + `world.gd`）

## 8. 灯河渡口：过关 / 回溯 / 全图照亮 / 不刷怪 / 留在地图中（本轮收尾）

③打通的关卡**全图照亮** ④**不刷怪** ⑤三关全通后可**留在地图中**，此时所有地图都亮且无敌人。

**结果**：断言 479 → **528**，变异 62 → **69**（全量 `--jobs 4` **69/69 符合预期**），

### 做法（要点）
- **换关 = 地图上的一件事**：清关 → 灯塔/灯河亮 → 走到灯塔下按 E → 面板「顺流/逆流/留步」。
  面板显示什么、按下去去哪、自检断言什么，**只有一个出处** `World.ferry_options()`
  （边界：第一关无逆流、最后一关无顺流）。
- **「已打通」只在一个地方写下**：`Main.stay_here()` 是 `_mark_cleared()` 的**唯一**调用点。
  原本 `sail_to()` 也记一遍 → 那条断言被两个独立的层各能单独满足 = **没牙**
  （变异实测：摘掉 `sail_to()` 那两行，0 条变红）。语义也更干净：
  **按下空格那一刻**才算打完，Boss 刚死、面板还挂着不算。
- **全图照亮靠保色相色阶** `Art.lit_palette(pal, 2.4)`（只提 `ambient` 只 1.18×，屏幕上不算"照亮"）。
  判据 = 单变量（同世界只关这一档 **2.4×**）+ 跨状态（同图、雾也关 **2.83×**）+ 绝对带 0.25~0.88。
- **不刷怪验的是状态**：`World.settle_cleared_state()` 是终态**唯一出处**
  （`setup()` 的 revisiting 与 `stay_here()` 都走它）。自检先**放开** `waves_disabled`，
  再补**阳性对照**（只抹掉第 0 段那两个标记 → 立刻刷出 5 只）。
- **留在地图 = 原地落定**（不重建世界，人不会被弹回出生点）。

### 本轮真正花时间的：三个**自检自身**的毛病（都不是玩法 bug）
1. **段数哨兵没牙** → 换 `CHECKS_MIN`（数**断言条数**）。
2. **数"名字数"照样没牙**：`_checks` 按名字索引，**同名断言会塌成一条** →
   把"同一断言跑两次"误报成"少跑了"，而且报的原因是"段内抛运行时错误"，**那轮根本没有**。
   → 数 `_ok()` **调用次数** + 配一条**重名哨兵**。它当场逮到一条**真重名**
   （循环两圈的 `★ 而且是**回访**进来的…` 漏了关名 → 后一圈静默覆盖前一圈）。
3. **`_ferry_sail()` 失败出口把面板留给 `_pump()`**：`_pump` 默认 `auto_draft`，

## 10. 墙影的**时间锚定** · 开始界面与自定义快捷键（558/558 · 变异 76）

用户三句话：「修一下雾与墙壁碰撞时的不协调」→ 澄清为**「墙周围的阴影一直乱晃」**、
「添加一个开始界面」、「可以自定义快捷键，放在开始界面的设置里」。

### 玩法/表现
- **照亮场是"重建那一刻的屏幕快照"，语义却是世界锚定** → 中间那 2~3 帧的旧数据必须
  **按相机位移挪回去再采**：`ruv = SCREEN_UV + (cam_xy − rebuild_cam)·(1,S)/(view_w,view_h)`。
  少了它 = 影子"冻 2~3 帧再窜一步" = 用户说的**乱晃**。
- **标题 = 三行菜单**（开始游戏 / 设置 / 操作说明），方向键回绕；「设置」= 重绑表，
  行数只有一个出处 `GameInput.REBINDABLE.size() + 2`（实测 20 行 / 一屏 9 行 → 必须滚进屏内）。
- **新加动作要进 `GameInput.ACTIONS`**（只 `_register()` 进 InputMap 不算）—— 又踩了一次。

### 自检（`_section_fog_wall_shadow` 的 ③ 重写，+30 条 → 558）
冻世界 + 只挪 `draw_cam` 64px（= 4×16px，落在照亮场格子边界）+ 三张图**共用同一张旧贴图**、
唯一变量是 Δ；一对正反 + 三条前提。踩到并修掉的四个坑：① **取景窗硬编 → 整块落在饱和区**
（现在整屏扫"雾层水平梯度最陡处"，并加 `fog_lag>0.004` 前提守门）；② **阴性对照量到了同一张图**
（`img_nomove` 抓在 `_rebuild` 之后 = `img_fresh` → 三个差全 0）；③ "把锚设成荒唐值"当接线哨兵
只有 1.04 倍余量（整屏被夹到同一 texel）；④ ★正 有条**平凡通过的后门**（uniform 从没发过时
两图用同一个错锚照样相同）→ 把 `sh_shift==64` 并进合取式。

### ⚠️ 收尾：一条**旧变异的 `forbid` 静默过期**

## 11. 出生地图「灯堡前厅」：一边明一边暗 · 暗侧通关卡 · 明侧守灯人

用户原话：「添加一个初始出生地图，这个地图是一边明一边暗，暗的那边通往关卡，
明的那边有守灯人，未来可能还会添加一些其他功能。」

### 做了什么
- **数据**：`Content.HUB` 单独一张表 + `HUB_INDEX = -1`，**不进 `LEVELS`**（`level_count()` 仍是 3）。
  `is_hub(i)` 是"是不是中枢"的唯一出处。新道具 kind `beacon`（主灯）/ `gate`（暗门）。
  `NO_TARGET = -99`（`-1` 被中枢占了，"不动"哨兵让位）。
  中枢**故意没有** `waves`/`boss`/`chests`/`braziers` —— 尤其火盆：要"消耗 3 连击"才点得着，
  而这里没敌人可打，连击恒 0，摆上去就是个点不着的摆设。
- **"一边明一边暗"**：不是调亮度（`ambient` 是全局 `CanvasModulate`，画不出半边），
  而是"一盏常亮主灯（980 / 1.35 / 带遮挡）+ 一道带门洞的分界墙（立在 `lit_x_max = 880`）"。
  分界线是**光自己划出来的**：实测主灯对暗侧窗的增量 = **0.000**（灯开着与关着一模一样）。
- **判据三条咬合**（同一帧相对 + 绝对增量 + 单变量）：明侧窗比底色亮 ≥0.08（实测 +0.197）/
  暗侧窗与底色差 ≤0.02（实测 **0.000**）/ 只关主灯 `shadow_enabled` → 暗侧 +0.103，
  而**墙前那一窗漂移 0.0002**（反向对照，把"灯变亮/全局变亮"排除掉）。同帧明暗比 **2.29×**。
  底色是**把主灯 `enabled=false`** 拿的 —— `HUB_BEACON_R` 980 > 画面 1280×1161，
  屏上根本没有"灯够不到的远处"可用。
- **世界/主循环**：`setup` 去掉含糊默认、`is_hub` 判定；`_roll_anchors/_roll_waves` 早退；
  `_update_waves` 在**读 `level["boss"]` 之前**收住（判据是"数据在不在"，不是 `is_hub`）；
  `up_target()` 第一关的上游永远是前厅；`ferry_options()` 中枢不看 `cleared`；
  `Main` 三处默认关都指 `HUB_INDEX`；`sail_to` 夹子下界放松；hub 入场对白一局只播一次。

### 踩的坑（一个大的 + 两个小的）
1. **⚠️ 自检的基准关被一起改掉了**：`Main._ready()` 里的 `show_title()` 会把 `prog["level"]`
   设成 `HUB_INDEX`，而自检那行 `main.prog["level"] = 0` 写在 `add_child(main)` **之前**
   → 被当场覆盖 → `_check_boot()` 建出中枢 → `_section_combat` 往没有 `enemy_scale`/`boss`
   的图上刷敌人 → 一串 `SCRIPT ERROR` → 每段在抛错处截断 → **512/528，红的全是
   "机器人打不死敌人""撞墙位置不对"这类看着毫无关联的断言**。
   修法：那行挪到 `add_child(main)` 之后；`spawn_enemy` 的 `enemy_scale` 改 `get(..., 1.0)`。
   可推广：**节点在 `_ready()` 里改的状态，自检对它的初始化必须在 `add_child()` 之后写。**
2. **暗门必须真的进 `props`**：只写 `goal: {kind:"gate", pos:...}` 不够 ——
   世界是按 `kind` 在 `props` 里认终点的，`goal_prop` 会是空的，**提示给不出来、按 E 没反应，
   而坐标看起来完全正确**（`Invalid access to property or key 'kind'`）。
3. **旧断言过期**：「第一关只有下游」在新设计下**本来就该红**（现在有三个方向：顺流/逆流回前厅/留步）。
   改成"三个方向齐全 + 新辅助 `_panel_target_of(id)` 断言逆流**指向出生地图**"——
   只断言"有 up 这一项"的话，把它改成指向第三关照样绿。
4. 变异表 `forbid` 第一次抄错断言名（漏了 `★ 【用户要的这条】` 前缀），被 `unknown_targets()`
   **40 秒**拦下 —— 前置校验的价值又体现了一次。
