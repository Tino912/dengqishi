## 硬约定
1. **`README.md` 是用户给的原稿，不要覆盖**。实现说明写 `IMPLEMENTATION.md` /
   `godot-lightknight/README.md`，原稿最多加一行指引。
2. **交付物必须能被验证**：真跑（真引擎/真浏览器），不接受「应该可以」，固化成一键脚本。
3. **多界面切换的缺陷测不到**（类型检查/构建/纯逻辑仿真覆盖不了），必须真浏览器走完整交互。
4. 断言针对真实状态；累计计数用基线增量，别硬编码。
5. **全绿 ≠ 有意义**：写完断言必须做一轮**变异测试**。
6. **绝对断言与相对断言要配对**：整片"比基准多多少"的断言在基准被改坏时全都不响。
7. **变异"没红"要先分清两种情况**：①补丁没打在生效的那一层；②**断言问错了问题**
   （对该失败方式天然不敏感）。②要**让旋钮转一下** —— 同一帧只改一个变量做前后对照，
   **不是把阈值调松**。本轮实例见下方「夜色 / 迷雾」。

## 一键脚本 / 当前基线（tools/）
- `tools/godot-lightknight.sh` — 完整自检 **594/594**，rc=0，连跑两遍 `report.json`
  **逐字节相同**，基线 md5 `b6b27e313f5d21188e9688368511cb5a`（出生地图「灯堡前厅」之后）。
  **全程约 55 秒** = 引擎 ~40（`--disable-vsync`）+ 导入刷新 ~8 + 汇总；跑两分钟以上
  通常是卡超时（脚本没起来），先 grep `SCRIPT ERROR|Parse Error`。
  ⚠️ **`--disable-vsync` 的收益只有 6%（42.9 → 40.2 秒）**，不是早先记的 2.15×
  —— 那个 86 秒是**脚本总耗时**，跟**引擎耗时**不是一个口径。见下 `godot-mutate.py`。
  ⚠️ **新加 `class_name` 的脚本必须先刷全局类缓存**（`.godot/global_script_class_cache.cfg`），
  否则报 `Parse Error: Identifier "xxx" not declared` —— 看着像"变量没声明"，其实代码没问题。
  脚本已**自愈**：`find src -name '*.gd' -newer <缓存>` 命中就先 `--import`（约 10 秒）。
  ⚠️ **它刻意不做 `rm -rf "$SHOTS"`** —— 沙箱批量删除保护**按 turn 累计**（同一 turn 内
  删超过 50 个就要求确认），而 shots/ 有 60 个文件 → `rm -rf` 会**卡住等确认**，
  症状是自检 3 分钟无输出且 `ps` 里连 godot 都没有。现在**只写不删**：截图按固定名字覆盖，
  跑完用 `find -newermt` 只读地列出"这一轮没重新生成"的文件。Godot 那步 `timeout` 200（不是 400）。
- `tools/godot-mutate.py` — 变异测试 **76 个**（`serial: True` 5 条碰真窗口）。**不走一键脚本**，直接调引擎
  （见文件头「倍速」一节）。跑法：串行（无 `--jobs`）+ 名字子串过滤（多子串 OR）+
  `--jobs N`（并发）；`DQ_VSYNC=1` 可关掉 `--disable-vsync`（做 A/B 用）。
  备份 `~/.cache/dq-mutate/src.bak`。
  ✅ **`--jobs 4` 实测可用**：全量 **824 秒 / 13 分 44 秒 · 62/62 符合预期**
  （串行按 40.2 s/轮推算约 43 分钟 → **3.1×**）。并发下单轮 31~39 秒 ——
  这类自检只吃 1~2 核，所以并行近乎线性。每 worker 一份工程副本
  `~/.cache/dq-mutate/wN/`（连 `.godot/` 一起复制 → 副本不必重新导入），
  各自就地改自己的 `src/`。
  ⚠️ **跑之前先自证**：用**未打补丁**的副本并发跑一轮、要求全绿；它确实**偶发**拦下过
  `★ 前提：真窗口能被设成测试尺寸`（4 进程抢 XWayland 窗口尺寸）。但**自证只是一次采样**、
  不是保险 —— 所以真正的修法是**把碰真系统的几条排除在并发之外**：变异表里标
  `"serial": True`，那 4 条**整组先单独串行跑完**，其余再并发。
  （旧记录写的"本机用不了并发、只能退回串行"**已证伪**，别再照抄。）
  ⚠️ **跑之前不许删 `report.json`**：第一版用 `unlink()` 保证"读到的是新报告"，
  结果撞沙箱批量删除保护（**按 turn、跨进程累计**），四个 worker 各撞一次 →
  **整批跑挂、日志也没了**。改成**只记 mtime、跑完必须变**（零删除）。
  ⚠️ 日志：`main()` 里行缓冲 + **并发路径在 worker 循环内逐条 `print(flush=True)`** ——
  `ThreadPoolExecutor.map` 要**等全部跑完才返回**，收齐再打印会让整批十分钟**一行都不出**，
  从外面看就是"卡住"（`ps` 里 python 和 worker 都活着）。
  ⚠️ **刻意不用 `rmtree`**（沙箱批量删除保护会拦 → 还原失败、坏源码留盘），用
  `copytree(dirs_exist_ok=True)` 覆盖式还原；⚠️ src 一改它就拒绝覆盖备份，先把
  `src.bak` **改名存档**（别删）再重跑。另有 `--list` / `--restore-only`。
  ⚠️ 基线后有**两道前置校验**（40 秒内跑完，省得白等整批）：
  ① `unknown_targets()` —— `expect`/`forbid` 对不上任何 `report.checks` 名字就退出
  （以前抄错断言名要跑完 27 分钟才说"预期没红"）；
  ② `stale_patches()` —— 每条 `edits` 的 `old_string` 在当前 `src` 里必须**恰好命中 1 次**
  （0 = 锚点过期，≥2 = 不唯一）。**改了源码里"长得像补丁目标"的那一行，就要核对变异表**：
  本轮「去掉高度视差」因 `float sink = … / view_h` 改名成 `float hz = …`，跑到第 54 条才炸。
  ⚠️ **变异的期望表只能写"确定的那一半"**：「退出全屏时立刻设尺寸」的效果分两半 ——
  调用时机确定（时序断言 5/5 红），**最终尺寸是竞态**（另两条 3/5、1/5 红）。
  偶发的那一半 **`expect`/`forbid` 两边都不能写**（写哪边都会随机报错）；留白 → 以"？额外"
  进日志（看得见、不参与判定）。它们有牙，归属另一条变异（「尺寸不下发」稳定让它们红）。
  **一条断言一个归属。**

## 本机环境坑
- **沙箱「批量删除保护」**：**按 turn 累计** —— 同一条命令里删 >50 个文件（或同一 turn
  里累计超 50）就会被拦，**而且是卡住等确认、不是报错退出**（`scope":"turn"`）。
  实测：一次 30 + 再一次 30 = 被拦；覆盖式**写** 60 个文件 = 不拦。
  → 还原/同步一律**覆盖式复制，只写不删**；真要多删就分到不同 turn 去删。
- 预置 `HTTP_PROXY/HTTPS_PROXY` → 本地回环 502，命令前 unset。
- **`/tmp` 只有 10MB**：`TMPDIR`/`--user-data-dir`/截图输出一律放 `~/.cache/` 下（否则莫名崩）。
- **GDScript 解析错误会让 Godot 挂住不退出**（打完 Parse Error 就不动了）。
  外面看到的现象只是"这轮自检好慢"。→ Godot 那步 timeout 别给太宽（200 秒够），
  一旦"代码没变慢却变慢"先 grep `SCRIPT ERROR|Parse Error`，别先怀疑性能。
- 无头浏览器只有 `google-chrome-stable`；**`--virtual-time-budget` 必崩**；`--dump-dom` 比
  `--screenshot` 稳。Godot `/usr/bin/godot` 4.7.2 + llvmpipe，`DISPLAY=:1`；
  **自检不能 `--headless`**（读不出 SubViewport 像素）。本机无声卡（代码对但听不到）。
- **bash 执行中会持续读脚本**：别边跑边改脚本（会报莫名语法错）；改完 `bash -n` 一下。
  ⚠️ **"边跑边改"包括变异测试在跑的时候** —— `godot-mutate.py` 会反复调用那个自检脚本，
  中途改它会污染整轮结果（本轮踩过一次：只能杀掉重跑）。要改脚本就先停测试。
- **新加 `class_name` 的脚本要刷类缓存**（同见上）：`.godot/global_script_class_cache.cfg`
  只在工程被扫描时重建。缓存旧时报的是
  `SCRIPT ERROR: Parse Error: Identifier "fs" not declared in the current scope` ——
  `var fs := WindowMode.new()` 那一行的类型推断垮了，于是 `fs` "不存在"。
  跑 `godot --headless --path <proj> --import`（约 10 秒）即可。
  ⚠️ 照这个报错去"补声明 / 改语法"只会越改越歪。

## Godot 版关键设计（改之前先读）
- 固定步长 `Main.advance(1/60)`，游戏与自检**走同一条代码路径**。
- 输入自己实现边沿检测（`GameInput.just()` + `set_override()`），**不用 `Input.is_action_*`**。
- **四种状态会冻结世界**：`dialogue` / `draft`（**开宝箱也是这个状态**）/ `shop`，
  以及 `World.waves_disabled` 沙盒开关。
  `_pump(...auto_draft/auto_dialogue/auto_shop)` 默认三个都点掉；少点一个 → 后面**成片变红**
  （敌人不动/镜头不跟/灯不亮），极难反查。面板收尾统一 `_resume_play()`。
- **随机源分家**：`_rng`(主仿真) / `_decor_rng` / `_shop_rng` / `_chest_rng` / `_layout_rng` /
  `_elem_rng`。**除 `_rng` 外一律不得走主仿真流**（主仿真流每步消耗由玩家走位决定）。
- **步数是货币**：为取景多 `_pump` 会挪动 RNG 流、撞掉几十条断言；`_shot()` 本身不推世界。
  `_write_png` **自己补 `.png`**（传 `"12-draft.png"` 会落成 `12-draft.png.png`）。
- **三选一两段式**：只有 `Q`/`E` 移高亮、`空格`/`回车` 拿走、`Esc` 放弃；`1/2/3`、`A/D`、
  `J`/左键**全部无效**（用户明确要求）；另有 **0.35s 装填窗口** `Main.DRAFT_ARM`。
- **对比前/后必须冻住其它变量**（半径里有 `combo`、`glow`；`glow` 写成 1.0 后**不再衰减**）。
- 脚下的烘焙光池**不认遮挡**，故意很小；真照明交给会被墙挡的 `PointLight2D`。
- `Bloom`（`BLEND_MODE_ADD`）必须显式 `queue_redraw()`。
- 遮挡体 = **屏幕上画出的整体轮廓（顶面 ∪ 南立面），只削底边 16px**（`LightRig.OCC_TRIM`）。
- 灯贴图必须**竖压 0.62**（= `YSQUASH`），否则地面南北比东西多照 70%。
- Boss 招式池**分阶段**：满血 phase 1 没有 `beam`。
- 关卡 `seed`：L1 10711、L2 20422；自检另钉 `LAYOUT_SEED = 20260925`。
- **rc=1 不等于断言红**：曾 152/152 全绿却每帧打 "Invalid access to property" →
  **必须单独看 `report.json.errors`**。

## 美术 / 素材层
- 素材**运行时加载**（绕开导入管线，裸仓库跑自检不需要 `.import`）；无 mipmap →
  贴图**预先降采样 256×256**。入口 `art.gd`。**程序化为主、贴图只做点缀**（渐变与粒子）。

  每个采样点加常数，压平比值型断言）。
- Godot 4 易错：`content_margin_*` 属于 `StyleBoxFlat` 不是 `PanelContainer`；内部类引用
  外层常量写 `Hud.C_XXX`；`var _ready := false` 撞 `func _ready()`。

## 道具 / 词条 / 守灯人
- **宝箱**每关 2 个，`E` 开 → 复用三选一面板 → 进**背包**；开过的不复活。
- **背包**只多带一把武器（`prog["bag_weapon"]`）+ 灯油（`prog["shop"]["oil_bank"]`）。
  `X` 换手（背包空时不动）；`C` 喝灯油（回 45%；没药/满血都不消耗）。
- **守灯人**商店：灯油 22 / **重铸** 45（词条推倒重来）/ **锤炼**（加条或升级，全 5 级后
  **不受理也不收钱**）。**8 条词条**全部落在**已有派生属性访问器**上，**别在别处再乘一遍**；
  **挂在「武器 id」上**（`prog["waffix"]`）→ 换手不丢。
- ⚠️ **加道具绝不能直接往 `level["props"]` 里塞**（会挪动 `_decor_rng` → 整关装饰换位 →
  像素断言成片变红）；宝箱走**单独的 `chests` key**、`_decorate()` 之后才入 props。
  **宝箱故意不 solid**（否则插进 `collide_wall` 把动线断言搞崩）。

## 布局随机化（宝箱 / 波次锚点 / Boss 场地每局重摇）
- `Main.run_seed` → `_layout_rng = make_rng(hash([run_seed, level_index, "layout"]))`；
  标题 `new_run()` 换种子，**死亡重开不换**。
- `level["chests"|"waves"|"boss"]` 的坐标**只是数量与兜底值**。宝箱避墙/避出生点/避灯塔/
  箱间距 320；锚点各有净空，**相邻锚点距离卡 460~900**（太近会顺手清掉下一波，太远
  链条被拉断、机器人只清得掉两波）。
- **可达性是最值钱那条**：`blocked()` 只查"点在墙里"，查不出"与玩家之间隔一道墙" →
  那波永远清不掉 → **关卡静默卡死**。用 `has_los` 做**链式**可达（第一波↔出生点，
  之后↔上一波；都对着出生点判会过严到退化兜底）。
  ⚠️ `has_los` 是**约束与断言共用**的函数，写坏了一起被骗；真正的独立证人是
  端到端的「机器人清完了三波」。
- 反直觉：**手写那份布局本身不满足链式可达**，它是按"绕过去"设计的。
- **`waves_disabled` 沙盒开关**：锚点随机后某波可能落进早期段落的活动范围 → 意外刷出 →
  被顺手清掉 → 弹三选一 → 世界冻结 → 几百行后看似无关的断言失败。
  → `Main.waves_off`→`World.waves_disabled` 在 `_update_waves()` **开头早退**；
  自检默认关，只有波次段/第二关段放开并先 `restart_level()`。
  ⚠️ 别在 setup 里标记（会漏掉"清一波弹三选一"，实测 29 条断言被跳过）。

## 元素 / 攻击发光 / 三图
- 元素是**五种不同形状**不是五个倍率：火=灼烧 3.0s/22%；毒=6.0s/10%+减速；冰=冻结 1.15s
  （**连外力速度都清掉**）；雷=麻痹+连锁**一跳**（`has_los` **隔墙不连**）；光=对 `shadow` 系
  ×1.30（**只对暗影系**，是"对策"）。`_elem_rng` 种子 `hash([run_seed,"elem"])`，**不带
  `level_index`** → 挂在武器 id 上（`prog["welem"]`）→ 换手不丢、过关不重摇；允许重复。
  弹丸颜色是**发射那一刻的快照**。攻击发光接进 `LightRig`（挥击灯 `"swing"`、弹丸灯
  `"proj:<pid>"`），**都带遮挡**；**`FX_LIGHT_MAX = 6`**（不封顶会拖垮帧率）。
- 三关：`court` 2400×1700 / `quarry` 2800×2000 / `river` 3000×2200（`lampdemon_shadow`）。
  `Art.body_kind()` 登记表：10 种敌人 → **9 套身子**。断言要写「**除「灯影」本身没有敌人
  落回兜底造型**」，不写"每种画出来不一样"（永远绿）。
- ⚠️ **给敌人的位移别走速度通道**：链锁牵引原是 `e.vx += cos*pw`，被冻结（清速度）和毒减速
  吃掉 → 同一条断言因"这局抽到什么元素"红绿。改成一次位移 `yank` + 清速度。

## 夜色 / 迷雾 / 起步攻击范围（更早一轮）
- **`BASE_REACH := 1.20`**（刀锋 66→79.2），`reach_mul()` 用**加法**（乘系数会把已有的
  "+0.12/级"断言搞失真）。**有两条绝对断言钉住**（`==1.20`、`swing_reach()==79.2`）。
  机器人交手距离从 `swing_reach()` 推（`press_in=rch*0.78`/`atk_at=rch*0.95`），
  不再写死 62/64/44 —— 否则它不会用远程武器，"时而清完三波、时而只清一波"。
- **夜色**：`LightRig` 的 `NIGHT_MIN/SPAN/BASE`；**旧版区间写错**（三关落点全在 `t=0`，
  永远最暗、图纯黑）。三关调色板提亮时**色相没动**，只抬明度。
  ⚠️ **地图提亮会让比值型像素断言失效**（底色 0.17 把 0.07 的光除成 1.4 倍）→
  遮挡那组改成看**增量**（光的贡献本来就是加法）。
- **迷雾 `src/fog.gd`**：**不能用 Light2D**（2D 光照只能加，`BLEND_MODE_SUB` 减 RGB 不减 alpha）。
  做法：屏幕切 **80×45** 格 → 每格算"被照亮多少" → 80×45 贴图 → 全屏着色器画雾 +
  三层倍频噪声雾絮。视线用**射线扇**（192 条/盏 × `Proj.ray_rect_dist` slab 法）。
  `World.step()` 里调（固定步长，雾絮时间取自 `world.time` → 漂动也可复现），每 0.05s 重建；
  有开关 `set_fog_enabled`；`KIND_SCALE` 给每类灯开雾半径系数（玩家 0.82）；
  `MIN_OPENER_R` / `OPENER_MAX=10`；**`MIST_MAX = 0.45`**（用户先后要过"最浓"1.0 与
  "淡一点、让地形可见"，最后量成 0.45 —— 见下面的曲线）。
  清关 `disperse()/reset_fade()/tick_fade()` 走 `World.tick_fx`。
- ⚠️ **雾浓这个数是量出来的，而且"淡一点"必须淡过拐点**。做法：**冻结世界**

## 挥击范围线 == 实际判定 · 伤害数字分级（上一轮）

- **根因**：同一次挥击有**两条独立算的几何**。
  - 判定：`w["arc"]` 与 `range * range_mul * reach_mul`；
  - 画线：角度**写死 0.9 rad**、射程还多乘了个 **0.9**。

  弩（`style == "shot"`，本来没有近战扇形）**也画了一条**出来。
- **修法（唯一真源）**：`World.swing_cone(w, arc_mul, range_mul)` 出几何 ——
  形状 = **半径 `SWING_INNER`(40) 的实心圆 ∪ 内径 40 → 外径 r 的扇形**（"钥匙孔"，
  近身贴脸也要打得到，不是从圆心起算的纯扇形）。

  - 画线 `World.cone_polygon(cone, facing, seg)`（**循环必须从 `i = 0` 起**，
    从 1 起会漏掉内弧在 `a1` 处那个顶点 → 画出来的线比真扇形多一小条，
    逐点比对会挂）。

## F11 全屏（最近一轮）

需求一句话："设置一个 F11 全屏"。难点**不在 API**，而在这台机器上
**退出全屏之后窗口尺寸回不去**。

### 实测的窗口行为（XWayland，屏 2560×1600）

| 时刻 | `window_get_mode()` | `window_get_size()` |
|---|---|---|
| 启动 | 0（窗口） | 1280×720 |
| 进全屏 | 3 | 2560×1600 |
| `set_mode(WINDOWED)` **当帧** | 0 | **2560×1600**（还报着全屏尺寸）|
| **下一帧** | 0 | **1270×1528**（WM 自己的主意）|

→ 在"当帧"里设尺寸会被 WM 下一帧那次覆盖整个吃掉。四种写法实测：

| 写法 | 退出全屏后拿到的尺寸 |
|---|---|
| 同一步里连着设（最自然） | ❌ 1270×1528 |
| `set_size.call_deferred` | ❌ 1270×1528（deferred 也还在同一帧）|
| 等落定之后再设（8 帧） | ✅ 1280×720 |
| 补设三次 | ✅ 1280×720 |

**这是稳定失败、不是偶发** —— 所以能写成断言 + 变异，不是 flaky。

### 实现：决策与真窗口分开

- `src/window_mode.gd`（`class_name WindowMode`，纯状态机，**自己不碰窗口**）：
  - `press(cur_mode, cur_size) -> int`：进全屏 → 返回 `WINDOW_MODE_FULLSCREEN`，
    记住 `saved_mode` / `saved_size`；退出 → 返回 `saved_mode`，把尺寸放进 `pending`、
    置 `left = RESTORE_DELAY`（6 步）。
  - `tick(cur_mode, cur_size) -> Vector2i`：每步调一次；`left` 没走完就返回 `ZERO`；
    走完后**每步核对** `cur_size == pending`，对不上就再设（上限 `MAX_TRIES = 10`），
    对上就收工（幂等）。
- `main.gd`：`advance()` 里**在状态机分发之前**处理
  `GameInput.just("fullscreen")` → `window_set_mode(fs.press(...))`，
  然后每步 `window_set_size(fs.tick(...))`（返回 ZERO 就不设）。
  放在分发之前 = **标题 / 对白 / 暂停 / 三选一 / 商店里都生效**。
- 两个刻意的设计点（各配一条断言 + 一条变异）：
  1. **`is_fullscreen()` 要认两种**（`FULLSCREEN` 与 `EXCLUSIVE_FULLSCREEN`）。
     只认一种的话，独占全屏下 F11 会再进一次全屏 → **玩家再也退不出来**。
  2. **进全屏时不许照抄"当前报的尺寸"**（刚退出又按回来那一帧报的是全屏尺寸）→
     有待还原的尺寸时以它为准。还**回最大化时不设尺寸**（硬设会把窗口从最大化里拽出来）。

### 自检（`_section_fullscreen()`，+24 条断言 → 442）

八组：① 什么算全屏 1 条 / ② 进全屏 3 条 / ③ 退出全屏 4 条（含**边界断言**：
前 6 步一步都不许动尺寸、第 7 步才动）/ ④ 重试与上限 3 条 / ⑤ 独占·最大化 4 条 /
⑥ 快按两下 3 条 / ⑦ **端到端真窗口 4 条** / ⑧ 界面无关 2 条。
排在**最末**（真切窗口时全屏 2560×1600 会拖慢软件渲染；像素采样用固定尺寸
SubViewport，所以窗口怎么变都不影响前面的判定）。

端到端实测：`按下前是不是全屏 0 → 按下后 1 → 再按一次 0`，`退出后尺寸回到原值 1`，
`按下次数 2`；标题界面那一轮同样成立。

### 7 个新变异（累计 50）

退出全屏时立刻设尺寸（`left = 0`）/ `is_fullscreen` 只认 `FULLSCREEN` /
进全屏照抄当前尺寸 / `tick` 去掉幂等那半条 / F11 只在 `state == "play"` 生效 /
**`ACTIONS` 里删掉 `fullscreen`** / **算出来的尺寸不下发**（`want.x < 0`）。
后三条分别复现了本轮真踩的三个坑（界面无关、采样表、忘了下发）。

### 本轮踩的坑

1. **同一条消息里改同一个文件 → 改动被盖掉**（本轮两次都栽在这）：
   - `main.gd` 的 `var fs := WindowMode.new()` 被同消息里 `advance()` 那次编辑盖掉。
   - `game_input.gd` 的 `"fullscreen"` **漏进了 `ACTIONS` 表** → F11 在真游戏里
     也完全没反应（采样只看这张表，`just()` 永远 false，**不报任何错**）。
   → 规矩：**一条消息只改一个文件**，改完立刻 `grep` 确认落盘。
2. **"决策对、接线漏了"只有端到端抓得到**：决策层 20 条断言全绿，
   只有 `★ F11 真的把窗口切成全屏` 红，报错是"按下次数 0"。
   → 一个功能有两层（算什么 / 有没有下发）时，**两层要分别有断言**。
3. **`class_name` 新脚本要先刷类缓存**（见上）。
4. **断言一改名，变异表里的 `expect` 字符串就悄悄失效**。重写尺寸那两条断言之后，
   变异 `退出全屏时立刻设尺寸` 的 `expect` 还留着旧名 —— 跑起来只会变成
   "预期变红却没有"，看不出是**抄错了名字**。这次是 `unknown_targets()`
   前置校验在开跑前就拦下了（基线绿了之后先拿全量断言名验一遍）。
   → **改断言措辞 = 顺手 `grep` 变异表里同名子串**，别等 45 分钟跑完才发现。

### 架构决定（照这个改，别自作主张塞进 LEVELS）
- `const HUB := {...}` 单独一张表，**不进 `LEVELS`**。`Content.HUB_INDEX = -1` 占一个关卡号，
  `Content.level_at(-1) -> HUB`、`Content.is_hub(i)` = **"是不是中枢"的唯一出处**
  （世界 / 主循环 / 自检都问它，不各写 `i < 0`）。
  → `level_count()` 仍然是 **3**（"本作三关""一关更比一关黑/狠""三图风格各异"都按三关两两比）。
- `Content.NO_TARGET = -99`（"不动"哨兵）：`-1` 被中枢占了。⚠️ 现在**没人读** `stay` 的 target
  （`Main._take_draft` 只对 down/up 走 `sail_to`），所以自检里那条量的是**行为**。
- `HUB` 里**故意没有** `waves` / `boss` / `chests` / `braziers`。火盆那条尤其要记住：
  它要"消耗 3 层连击"才点得着，而中枢**没有敌人可打** → 连击恒 0 → 摆上去点不着。
  **中枢里所有交互都必须是"不需要战斗资源"的。**
- 新道具 kind：`beacon`（主灯，`PROP_TABLE` r26/h132/solid）、`gate`（暗门，r40/h96/solid）；
  美术在 `Art._beacon` / `Art._gate`；`Fog.KIND_SCALE["beacon"] = 1.0`。
  ⚠️ **门必须真的进 `props`**：世界是按 `kind` 在 `props` 里认"哪一个是终点"的，
  只写 `goal: {kind:"gate", pos:...}` 不够 —— `goal_prop` 会是空的，
  **提示给不出来、按 E 没反应，而坐标看起来完全正确**（第一次跑就栽在这儿）。

### "一边明一边暗"是怎么来的（不是调亮度）
`ambient` 走全局 `CanvasModulate`，**画不出半边**。实际是：
① 明侧一盏**常亮主灯** `beacon`（`HUB_BEACON_R = 980`、`HUB_BEACON_E = 1.35`、
`shadows = true`）；② 分界墙两段立在 `lit_x_max = 880` 上，中间留 180 宽门洞。
→ 分界线是**光自己划出来的**，暗侧是**真的收不到光**（实测主灯对暗侧窗的增量 = **0.000**）。

实测（雾关掉；两个取样窗都在画面里、都离玩家灯火 ≥240；玩家灯火半径**冻在 150**）：

| 量 | 值 |
| --- | --- |
| 明侧窗 0.368 / 暗侧窗 0.161（距主灯 172 / 529，后者在墙背后） | 同一帧 **2.29×** |
| 主灯 `enabled=false` 之后两窗 | 0.170 / 0.161（同一块地板同一种夜色） |
| 主灯对明侧的增量 / 对暗侧的增量 | **+0.197 / +0.000** |
| **只关 `shadow_enabled`**：暗侧窗 / 墙前窗 | 0.161 → 0.264（**+0.103**）/ 漂移 **0.0002** |

⚠️ **底色不能用"屏上找一处灯够不到的远处"**：`HUB_BEACON_R` 980 > 画面 1280×1161，
屏上几乎没有那种地方 → 底色是**把主灯 `enabled=false`** 量出来的
（灯层每帧只写 `position/texture_scale/energy`，**不碰 `enabled`**，所以拧得住；
而 `energy` 每帧被写回，改它没用）。
⚠️ 前提两条：**玩家灯火半径冻在 150**（显式清零升级与恩赐）、**两个窗灯关掉后一样亮**。
