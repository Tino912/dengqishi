## 硬约定（9 条，展开见 DETAIL）
1. 根 `README.md` 是**用户给的原稿，不要覆盖**；实现说明另开文件（`IMPLEMENTATION.md`、
   `godot-lightknight/README.md`）。
2. 交付物必须**真跑起来**验证（真引擎 / 真浏览器），不接受「应该可以」，固化成一键脚本。
3. **全绿 ≠ 有意义**：写完断言必须跑**变异测试**（改坏实现，只有对应断言该变红）。
   - 变异"没红"先分清三种：①补丁没打在生效层；②**断言问错了问题**（要"让旋钮转一下"，
     同一帧只改一个变量做前后对照，不是把阈值调松）；③`expect/forbid` 抄错断言名。
   - **量哪一层，就把别层冻住**；**一条断言被两个独立的层各能单独满足 = 没牙的烟测**。
   - 期望表只写"确定的那一半"；`forbid` 只列**基线里是绿的**断言。
   - **"没人读的数字"不是判据**：面板项上那个 `target` 没人读 → 只能断言**行为**（面板上
     "留步"要量"世界有没有重建"，不是断言那个数等于某个常量）。
4. **判据只有一个出处时，才对得起"改坏它就会红"**：同一个判断在 N 处各写一遍 →
   迟早在第 N 处漏掉。收成一个总闸函数（如 `Content.is_hub`），并在关键处刻意再问一次。
5. **绝对断言要与相对断言配对**；绝对像素差随亮度缩放 → 要么按亮度归一化，要么配相对对照。
6. **断言"取错帧/读错层"会让它恒真/恒假**：采样区只装你要盯的那一层。
   底色不要"在屏幕上找一块暗的"—— `HUB_BEACON_R` 980 > 画面 1280×1161，
   屏上几乎没有"灯够不到"的地方 → **把灯 `enabled=false` 拿底色**。
7. **哨兵本身也要验有没有牙**：段数哨兵没牙 → 数 `_ok()` **调用次数** + 配重名哨兵。
8. **测试辅助函数的失败出口也要把场面收干净**（面板没收掉 → 下一个 `_pump()` 自动选 →
   世界重建 → 调用方攥的引用成 previously freed → 段内静默截断后面所有断言）。
9. **`Main` 这种"自己在 `_ready()` 里改状态"的节点，自检对它的初始化必须写在
   `add_child(main)` 之后** —— 否则那行是写完就废的，且只在别处表现为"一堆无关断言变红"
   （见 README 二.23.6）。

## 最近几轮（细节见 DETAIL 同名小节 / README 二.23 / 二.22 / 二.21）
- **出生地图「灯堡前厅」**（594/594 · 变异 83）：用户要的"一边明一边暗，暗的那边通往关卡，
  明的那边有守灯人"。做法 = `HUB_INDEX = -1` 占一个关卡号但**不进 `LEVELS`**（`level_count()`
  仍是 3）；明暗**不是调亮度**，是"一盏常亮主灯 + 一道带门洞的分界墙"合起来划的。
  判据三条咬合：明侧窗比底色亮 ≥0.08 / 暗侧窗与底色差 ≤0.02（实测 **0.000**）/
  只关主灯 `shadow_enabled` → 暗侧 +0.103 而墙前漂移 **0.0002**。
  ⚠️ 教训：**`show_title()` 会把 `prog["level"]` 设成 HUB_INDEX**，自检那行初始化必须放在
  `add_child(main)` 之后（否则基准关变成前厅 → 20+ 条无关断言变红）。
- **墙影的时间锚定 · 开始界面与自定义快捷键**（558/558 · 变异 76）：照亮场旧数据要
  **按相机位移挪回去再采**（`rebuild_cam`），否则"墙周围的阴影一直乱晃"；标题改成三行菜单，
  「设置」= 重绑表（改键走玩家路径、成对量 `binds` 与 `InputMap`、立刻存盘、能读回）。
  ⚠️ 三个教训：**取景窗要现场扫**；**哨兵读 uniform 要接住 `null`**；
  **uniform 被第二处消费后旧变异的 `forbid` 会静默过期**。
- **灯河渡口 · 全图照亮 · 不刷怪 · 留在地图中**（528/528 · 变异 69）：换关 = 地图上的一件事
  （`World.ferry_options()` 唯一出处）；「不刷怪」验**状态**不验开关；「留在地图」是**原地**落定。
- **迷雾的高度 / 体积 / 飘移**；**雾长在地图上 · 伤害光圈变小 · 变异测试倍速**。
