# 灯骑士 · Godot 版

用 Godot 4 把「灯骑士」做下来的第二个实现。它**起步**于一次迁移实验，但现在已经不
只是实验了 —— 见下面「四、与 Web 版的关系」。

最初要单独考察的那件事是：

> **用 Godot 的 `Light2D` + `LightOccluder2D`，光能不能真的被墙挡住。**

Web 版的光照是 Canvas 合成手搓的（全屏压暗 → `destination-out` 挖洞 → 叠暖光）。
那套做法**没有遮挡关系，光会穿墙**——对「地图黑暗，只有灯骑士周围些许亮」
这个核心机制来说，是质变级的差别。结论：**能挡，值得迁移**（见 二.1）。

在此之上，Godot 线继续往前走了：**8 把武器 / 19 个技能**（每把武器一套自己的技能、
不同的连击门槛与冷却）、**精英词缀**、**肉鸽三选一**、以及**第二关「无芯之暗」**
（火盆与不死再生、盲女同行、分阶段 Boss）。最近两轮又做了 **HUD 自绘重制 + 战斗特效贴图化**
（见 二.9）、三选一改成**只有 `Q`/`E` 移动、只有 `空格`/`回车` 拿走**（见 二.8），
以及 **宝箱 / 背包栏（多带一把武器）/ 守灯人的重铸与锤炼**（见 二.10）。

一、运行
--------------------------------------------------------------------

```bash
# 一条命令：真实引擎里跑完整自检，产出 shots/*.png + shots/report.json
tools/godot-lightknight.sh
```

预期输出结尾是 `断言 222/222 通过` / `全部通过 ✅`，退出码 0。全程约 14 秒。

手动跑 / 想自己玩：

```bash
cd godot-lightknight
godot --path . res://scenes/main.tscn --rendering-driver opengl3
```

按键：`WASD` 移动　鼠标瞄准　`J`/左键 挥击　`Shift`/`Space` 冲刺　`1`/`2`/`3` 技能　`E`/`F` 交互
　`X` 换手（手持 ↔ 背包武器）　`C` 喝灯油（背包里的回血道具）
　`Enter`/`Space` 确认对白　`R` 重开　`Esc` 暂停
　（清空一波后会弹三选一：**只有 `Q`/`E` 能左右移高亮，只有 `空格`/`回车` 能拿走**，
　`Esc` 放弃这次。见 二.8。地图上的**宝箱**开出带词条的武器、**守灯人**能重铸/锤炼武器，
　见 二.10。）

> 自检必须**带显示环境**跑（X11 或 XWayland）。它要读 `SubViewport` 的像素来判定
> 「黑不黑、亮不亮、光有没有被挡住」，`--headless` 的 dummy 渲染器读不出画面。

二、验证结果
--------------------------------------------------------------------

### 1. 遮挡照明（最初那条结论）

同一场景、同一采样点、**只切换 `PointLight2D.shadow_enabled` 这一个变量**：

| 采样点 | 开阴影 | 关阴影 |
| --- | --- | --- |
| 墙前（灯与墙之间） | 0.3198 | 0.3198 |
| **墙后** | **0.0238** | **0.0829** |
| 射程外（同帧基线 = 地板底噪） | 0.0241 | — |

```
开阴影时：墙后 0.0238 ≈ 射程外 0.0241   → 比值 0.99×，墙后已被压到「照不到」的底噪水平
关阴影时：墙后 0.0829 ≈ 射程外 0.0241   → 比值 3.44×，说明光其实够得着，只是被墙挡了
墙后亮度降幅 71.3%　墙前/底噪 13.27×
```

「同帧基线」是这套实验的关键：`s_far` 取在灯半径之外、完全照不到的位置，
用**同一张图里**的它当底噪，才能排除「墙后本来就照不到、所以怎么测都暗」这个伪因。
`shots/05-occlusion-on.png` 与 `06-occlusion-off.png` 是这一组的对照截图——
开阴影那张，阴影边界从墙的东沿切线般拉开，墙后整片全黑。

### 2. 灯必须是「地面正圆」而不是「屏幕正圆」

2.5D 斜轴测下，屏幕上的正圆投到地板上是椭圆，会导致「南北方向比东西方向亮 70%」。
做法是把灯的贴图**纵向压扁 0.62**（与投影同一个 `YSQUASH`），于是它投到地面正好是正圆。
实测地面等距的东/北两点：

```
东 0.0750 / 北 0.0750 = 1.0000     （屏幕正圆会是 ~1.65）
```

### 3. 遮挡体的摆法

结论来自迁移前的两次探针（`godot-probe/`，见两份探针 README）：

- 贴**地面足迹** → 光会从墙顶翻过去照到墙后（实测墙后亮 10 倍），不行；
- 轮廓四边**均匀内缩** → 会从墙顶漏光，不行；
- **贴屏幕上画出来的整体轮廓（顶面 ∪ 南立面），只把底边削掉 16px** → 唯一正确解。

削底量直接决定「墙脚受光高度」：削 8px 在侧光下完全亮不起来，削 0 则墙脚全黑。
所以 `LightRig.OCC_TRIM = 16.0` 是个有依据的常数，自检里有三条几何断言看着它。

### 4. 八把武器 / 19 个技能：**特效**要真的分开，不是改数字

这是这一轮新增内容里最容易糊弄过去的地方 —— 把 8 把武器写成同一套挥击、只换
`dmg` 数字，断言照样能全绿。所以判据不是「伤害不同」，而是**打出来的特效种类不同**：

| 武器 | 手感定位 | 技能（连击门槛 / 冷却） |
| --- | --- | --- |
| 灯刃 `blade` | 最初的短刃，连击攒得最快 | 旋斩 4/2.2　灯爆 12/7.0 |
| 双灯刃 `twin` | 最快，单下很轻，靠连击层数顶伤害 | 乱影刃 4/2.4　双旋 11/6.0 |
| 长明枪 `spear` | 距离长、突刺强，**技能最多** | 掠光刺 3/1.8　连灯刺 9/5.0　长明贯 18/10.0 |
| 锁灯 `chain` | 近战里够得最远，能把影子**拽回来** | 链锁 5/3.0　环链 13/6.5 |
| 烬锤 `hammer` | 慢、重、范围极大，**只有一招** | 撼地 7/3.6 |
| 灯镰 `scythe` | 弧最宽，一扫小半圈；**别停** | 回旋 5/2.6　噬影 14/8.0　月环 22/11.0 |
| 灯弩 `crossbow` | **唯一远程**：挥击不再是刀弧，而是射出光矢 | 三连矢 3/2.0　穿影矢 10/5.5　灯雨 20/10.0 |
| 灯杖 `staff` | **唯一法术**：能在黑暗里「留下」东西 | 灯球 6/5.0　护光 14/9.0　陨光 24/12.0 |

自检把 8 把武器 / 19 个技能**逐个跑一遍**，每次出手后立刻采一次 `effect.kind`
（`beam`/`muzzle` 这类只活 0.06~0.2 秒，等 `_pump` 完再看就已经过期了 —— 这一条
曾经因此漏判）。实测：

```
8 把武器　19 个技能　玩家侧特效 7 种
burst, muzzle, pillar, pull, ring, slash, zone
```

外加 **Boss 独占的 `beam`**（吸灯光束 / 回旋光刃），归 Boss 那一段验。
这些特效背后是有行为的，断言也照着行为写，而不是照着"画面有东西"写：

- `pull` 链锁真的把敌人拽近：**420 → 274.8px**（`拉近 > 40px` 才算过）
- `zone` 灯球真的按 tick 反复结算，不是只打一下：1.3 秒内总伤害 **122.6**，命中集 ≥ 1
- `bow_pierce` 一根光矢真的穿过 ≥ 2 只排队站着的敌人
- `staff_ward` 护盾期间被咬**不掉血**
- `scythe_devour` 噬影窗口内造成伤害真的**回血**

`shots/11-weapon-staff-orb.png` 是灯杖的一张实拍：HUD 上是「武器 灯杖」，
左下角三个技能各自标着连击门槛（灯球 6 / 护光 14 / 陨光 24），
画面中央是一颗留在原地、持续灼烧的灯球 —— 与初始的灯刃完全不是一种东西。

### 5. 第二关「无芯之暗」+ 肉鸽循环

设计稿里有一句：「在其中一关，没灯芯，黑暗中怪和 Boss 不断再生」。第二关就是这一关。

| | 第一关「灯堡外庭」 | 第二关「无芯之暗」 |
| --- | --- | --- |
| 地图 | — | **2800×2000**（更大） |
| 环境亮度 `ambient` | 0.9 | **0.955**（更黑） |
| 敌人倍率 | 1.0 | **1.18** |
| 墙体 | — | 16 面 |
| 机制 | — | **火盆 3 座**、未点满则死亡再生、盲女同行 |
| Boss | 噬灯者·幼体 | **噬灯者**（devourer，带护佑减伤） |

- **再生**：火盆没点满时，死掉的影子会**复活**（自检里实测再生 5 次）；
  点满 3 座火盆后再生停止、Boss 的护佑（减伤 55%）同时解除。
- **盲女**：古老灯芯所化，跟着你走，**靠近时光照半径恰好多 52**
  （实测 `150 → 202`，差 0.0 误差）—— 就是设计稿里那句
  「可你在我身边时，我就感到格外亮堂」。她不会被攻击、不挡路，是「灯」不是「队友」。
- **分阶段 Boss**：噬灯者的招式池**随血量阶段变化**。这点很关键 ——
  满血时是 phase 1，池子只有 `dash/dash/slam/summon`，**再打也放不出光束**；
  掉到 1/3 才进 phase 3，池子里才有 `drain`（吸光）和 `sweep`（横扫）。
  自检因此先把它打到 phase 3 再验 `beam` 出没出。

**肉鸽循环**：清空一波 → 弹**三选一**（3 个选项，可能是恩赐，也可能是换武器）。
整个自检跑下来共发生 **7 次**三选一。选它是真的改东西：

- 选「武器」→ `prog["weapon"]` 与场上 `player.weapon_id` 同时换掉
- 选「恩赐」→ 恩赐入账，且**数值真的作用到派生属性上**：
  「灯芯·锋」提高伤害、「灯芯·明」提高光照半径、「灯芯·疾」降低挥击冷却、
  「省火」降低技能消耗（但有下限 1，不会白嫖）

**14 个恩赐**（灯芯·坚/锋/疾/明/远/通/锐、噬影、火种不熄、越战越亮、影步、省火、
灯油丰沛、灯灭之环）。**5 个精英词缀**，让同一个精英每局不一样：
燃（死亡爆火圈）、韧（减伤 35%）、疾（更快更勤）、噬（额外咬掉连击）、障（每 4 秒挡一次伤害）。

波次编排也做了种子随机（`_roll_waves`）：每局敌人组合与数量不同，但**完全可复现**。

### 6. 机器人试玩 90 秒（不预设数值，只看循环通不通）

```
击杀 32　最高连击 18.0　最低生命 67.0　清空波次 3/3　三选一 3 次　阵亡 0　打到 Boss ✅
```

机器人用真实输入（`GameInput.set_override()`，走 `just()` 边沿）驱动世界，不读内部
状态作弊。它同时是**肉鸽循环的端到端证明**：它会自己清波、自己点三选一、
一路打到 Boss 区。这一段曾经抓到两个隐蔽的 bug：

- 清空一波后世界被三选一面板**冻结**，机器人不会选 → 卡死在那，症状是
  「击杀数停在第一波、Boss 永不出现」。看起来像战斗坏了，其实是界面没点。
- 死亡后停在死亡菜单里空转，后面几十秒**静默**浪费，同样表现为「击杀数不动」。

### 7. 三层验证

| 层 | 命令 | 验的是什么 |
| --- | --- | --- |
| 编译 | `godot --headless --path . --import` | GDScript 静态类型/语法全过 |
| 仿真 | 自检里的逻辑段 | 波次、Boss 三阶段、连击衰减、技能门槛等纯逻辑 |
| **真引擎** | `tools/godot-lightknight.sh` | 222 条断言，含**像素级**的遮挡对照与灯形状判定 |
| **变异** | `tools/godot-mutate.py` | 故意改坏实现，确认**只有**对应断言变红（证明断言不是摆设） |

自检是**确定性**的：随机数全部走 `level["seed"]` 播种（第一关 10711，第二关 20422），
连跑两遍 `report.json` **逐字节相同**。这条曾经被破坏过，原因是
`EnemyState.create()` 里用了**全局未播种的 `randf()`** 来决定敌人的绕行相位 ——
而那个相位是**进仿真**的（`sin(e.t * 1.6 + e.wob)` 直接加进 `vx/vy`），
所以每趟跑出来的世界都不一样。症状极隐蔽：断言照样全绿，只有机器人试玩那段数值每次不同。
修法见 六.8。

### 8. 三选一的输入规则：只有 Q/E 移动，只有空格/回车拿走

原来的三选一是 `1`/`2`/`3` **直接选中**、`←`/`→` 移光标。问题是**误触的代价太大**：
清空一波往往正打着手，`1`/`2`/`3` 又紧挨着技能键，手指一滑就把这一局的选择赔进去了。

现在改成**两段式**：

| 动作 | 键 | 其余一律无效 |
| --- | --- | --- |
| 左移高亮 | `Q` | `A` 不行（`A` 是移动） |
| 右移高亮 | `E` | `D` 不行 |
| 拿走高亮那张 | `空格` / `回车` | `J` / 鼠标左键（攻击）不行 |
| 放弃这次 | `Esc` | —— |

再加一条 **0.35 秒装填窗口**（`Main.DRAFT_ARM`）：面板刚弹出的 0.35 秒内按确认**不生效**，
底部会显示一条装填进度。理由是"清波那一瞬间玩家手上常常正按着空格在冲刺"，
这个边沿会被面板吃到 —— 换成"必须停一下再确认"，误触就消失了。

这一段在自检里是**逐条可失败的断言**，不是"看起来该是那样"：

```
面板刚弹出时还没装填完 ✅
装填窗口内按确认无效（防误触：清波瞬间常在连打空格冲刺）✅
1/2/3 在三选一里已彻底失效（不再直接选中）✅
A/D 不会移动三选一高亮 ✅
J 不能确认三选一（攻击键在这里无效）✅
E 把高亮右移一格 ✅ ／ Q 把高亮左移一格（回到原位）✅
Q 从第一格再左移会绕到最后一格 ✅ ／ 绕回来仍是原位（左右对称）✅
确认拿走的就是高亮那一张（不是第一张）✅
```

其中"**每一条都要能真的失败**"这点很关键：`1`/`2`/`3`、`A`/`D`、`J` 这三组
如果代码里还留着老分支，对应的断言立刻变红；把断言删掉就检测不到了（这坑踩过，见 六.13）。

### 9. UI 与特效这一轮的翻新

用户要的是"整体 UI 和特效更好看一些"。这一轮做了三件事，**都不动玩法逻辑**：

1. **HUD 全部改成自绘控件**。原来 HUD 用 `StyleBoxFlat` 堆，做不到渐变条、辉光、
   扇形冷却这三样。现在血条/灯条/Boss 条是 `RBar`（渐变 + 滞后残影 + 冷却刻度 + 告急闪烁），
   技能格是 `SkillChip`（热键牌 + 连击菱形 + 冷却线），三选一是 `DraftCard`
   （渐变卡面 + 徽记 + 受选上浮与金描边），另有 `ArmBar` 装填条与 `PanelLamp` 角灯。
   卡片按 `_boon_sig` 签名缓存，只在内容变了才重建。
2. **光晕改成真渐变贴图**。原来 `Art.glow()` 是**几十个同心圆**叠出来的，凑近看是一圈圈
   同心环。现在换成运行时生成的 256×256 `soft_dot`（smootherstep 衰减），
   并且**预先降采样**（运行时贴图没有 mipmap，不降采样会有采样噪点）。
3. **战斗特效接上真素材**。挥击弧、命中火花、弹道拖尾、火盆/灯塔火焰、
   击杀余烬与烟，全部换成 Kenney 粒子包里的贴图（`Art.tex()` / `tex_rot()`），
   位置与旋转照旧由代码算 —— 随机项一律走种子的 `_rng`，所以**确定性不变**。

素材与许可（都在仓里，可整包复制）：

| 素材 | 用途 | 来源 | 许可 |
| --- | --- | --- | --- |
| `assets/vendor/kenney_particles/*.png` | 火花/烟雾/光斑/斩击/拖尾 | [Kenney Particle Pack](https://kenney.nl/assets/particle-pack) | CC0 1.0 |
| `assets/fonts/LXGWWenKai-Regular.ttf` | 标题、连击数等展示字体 | [霞鹜文楷 LXGW WenKai](https://github.com/lxgw/LxgwWenKai) | OFL-1.1 |

> **素材是"运行时加载"的**，故意绕开 Godot 的导入管线：
> `Image.load_from_file(ProjectSettings.globalize_path(...))` → `ImageTexture.create_from_image`。
> 这样 `--import` 之外的一键自检**不需要** `.import` 文件，也不会因为缺 `.godot/imported`
> 而在裸仓库里读不到图。代价是没有 mipmap / 压缩（所以就手动降采样到 256）。

### 10. 宝箱 / 背包 / 守灯人（重铸与锤炼）

这一轮加的是"**局内多一把武器 + 给武器加词条**"这条线。四件事：

| 东西 | 在哪 | 说明 |
| --- | --- | --- |
| 宝箱 | 每关 2 个 | 按 `E` 开，从**3 把**里挑一把，选中进**背包**；开过的箱子不会复活 |
| 背包栏 | 右下角 | 手持武器 + 它的词条 + 备用武器 + 灯油存量 |
| `X` 换手 | 任意时刻 | 手持 ↔ 背包 互换；**背包空时什么都不做**（不做"把自己缴械"） |
| `C` 喝灯油 | 任意时刻 | 消耗一件回 45% 生命；**没药 / 满血都不消耗**（不让人白扔一瓶） |
| 守灯人 | 每关 1 个 | 按 `E` 交谈，开商店：买灯油（22 灯火）、重铸（45）、锤炼（30 + 15×等级和） |

**重铸 vs 锤炼**（这次最容易做含糊的一处，所以说死）：

- **重铸** = 把词条**全部推倒重来**：随机 1~3 条、等级归 1、彼此不重复。
- **锤炼** = 没满 3 条就**加一条**；满了就**升一级**；全练到 5 级后**不再受理，也不收钱**。

词条一共 8 条，全部落在**已有的派生属性访问器**上（不在别处再乘一遍）：

| 词条 | 效果 | 落点 |
| --- | --- | --- |
| 锋 | 伤害 +12% | `damage_mul()` |
| 疾 | 挥击冷却 −10% | `attack_cd_mul()` |
| 远 | 攻击范围 +12% | `reach_mul()` |
| 锐 | 暴击率 +8% | `crit_chance()` |
| 噬 | 击杀回复 3 点生命 | `_kill_enemy()` |
| 明 | 光照半径 +22 | `player_light_radius()` |
| 火 | 每次命中额外 +0.15 连击 | `combo_bonus()` |
| 省 | 技能连击消耗 −1（最低 1） | `skill_cost()` |

**词条挂在「武器 id」上，不是挂在"当前手持"上**（`prog["waffix"] = {武器id: [{id,lv}]}`）。
所以换手不丢、换回来还在，背包里那把也各自带自己的词条；实测断言里专门验了这一条。

两条设计决定，都是为了**别把已经量好的世界搅动**：

1. **宝箱不写进 `level["props"]`，而是单独一个 `chests` key**，并且在 `_decorate()`
   **之后**才入 `props`。因为 `props` 里每一项都要 `_decor_rng.randi_range` 抽一个 seed，
   而 `_decorate()` 又会躲开已有道具 120px —— 提前加进去，整关装饰都会换位置，
   依赖装饰的像素断言会**成片**变红。实测：加宝箱前后 `report.json` 里除新段落外的数字**逐字节未变**。
2. **宝箱故意不 solid**。它是个"交互点"不是障碍；设成实心会插进 `collide_wall` 的推挤里，
   而动线与撞墙那几条断言是拿现有道具布局量出来的，多一个实心体就可能把玩家顶到别处。

**随机源分了三条**（`_rng` 主仿真 / `_decor_rng` 装饰 / `_shop_rng` 商店 / `_chest_rng` 宝箱）。
商店与宝箱的随机**绝不能走 `_rng`** —— 那是主仿真流，动它会把之后所有世界演化挪掉。

#### 这段的断言是怎么写"死"的

一共 61 条（222 总数里），要点是**每一条都能真的失败**。写完之后做了一轮**变异测试**：
故意改坏 6 处实现，确认**只有**对应的断言变红、没有连带误伤：

| 故意改坏 | 变红的断言 |
| --- | --- |
| `swap_weapon()` 改成空操作 | 按 X 与背包武器互换 · 换手后玩家手上真的换了武器 |
| `damage_mul()` 里删掉「锋」 | 词条「锋」真的进了伤害倍率 |
| `_can_temper()` 去掉等级上限 | 词条全部到上限后锤炼不可点了 |
| `use_potion()` 里 `healed` 置 0 | 按 C 喝灯油会回血 · 回血量正好是 45% 最大生命 |
| `apply_chest()` 不写 `bag_weapon` | 宝箱选中的就是高亮那一张 · 背包已满时换下旧的 · 手持没词条那把时「锋」回到 0 |
| 移动高亮时不带面板文案 | 宝箱面板按方向键后标题与提示不会被重置成三选一 |

最后一条是自己刚踩的坑：`_draft_input()` 每次按 `Q`/`E` 都会重调 `show_draft()`，
不把文案一起带上，**宝箱面板一按方向键就会退回三选一的标题**。
现在标题/副标题/底部提示存在 main 上（`_panel_title` 等），三选一与宝箱共用重画路径。

**三个会让世界冻结的界面**（这是本项目最容易把自己搞死的地方）：
`dialogue`（对白）、`draft`（三选一，**开宝箱也走这个状态**）、`shop`（守灯人商店）。
`_pump(n, hold, auto_draft, auto_dialogue, auto_shop)` 默认**三个都自己处理掉**；
少点一个，后面所有段落会成片变红（敌人不动、镜头不跟、灯不亮），极难反查。

```
    │   ├── game_input.gd    输入映射 + 固定步长边沿检测 + 测试注入

    ├── art.gd               程序化美术 + 素材加载层（glow 渐变、tex/tex_rot、粒子）
    ├── hud.gd               HUD（CanvasLayer，不受 CanvasModulate 影响）+ 自绘控件
    │                        + 三选一/宝箱面板 + 背包栏 + 守灯人商店
    ├── bloom.gd             加法混合叠加层
    ├── main.gd              状态机（title/play/dialogue/menu/draft）+ 固定步长驱动
    └── selfcheck.gd         真实引擎里的自检（推进世界 + 采样像素 + 判定）
```

几个刻意的设计选择：

- **数据 / 逻辑 / 绘制三层分开**。`content.gd` 是纯数据，`world.gd` 是纯状态推进，
  `art.gd` 只负责画。所以自检能直接读世界状态做断言，不需要去解析画面。
- **程序化为主、贴图只做"点缀"**。几何（地形、角色、灯）依旧全用 `draw_*` 画出来，
  外部贴图只用在"渐变/粒子"这类手画不好看的地方。好处仍是工程可整包复制、
  素材都带许可；代价是贴图**运行时加载**（见 二.9 的注）。
  CJK 字体优先用仓库里的霞鹜文楷，取不到时回退系统 `/usr/share/fonts/noto-cjk/`。
- **固定步长，游戏与自检走同一条代码路径**。`Main.advance(1/60)` 既被 `_process`
  的累加器按真实帧驱动，也被自检直接调用 N 次（自检把 `Main.manual` 打开，
  `_process` 直接 return，所以 `await` 渲染帧期间世界**不会**偷偷推进）。
  自检才有意义：它跑的就是玩家会跑的那条路径。
- **输入自己做边沿检测**，不用 `Input.is_action_just_pressed()`：世界是按固定步长
  推进的，自检更是脚本直接驱动，基于帧的 `just_pressed` 语义在这种驱动方式下不可靠。
  另外提供 `set_override()`，让自检完全不依赖操作系统的输入栈。

四、与 Web 版的关系
--------------------------------------------------------------------

**核心机制差异（迁移的收益）**

| | Web 版 | Godot 版 |
| --- | --- | --- |
| 光被墙挡 | ❌ 光穿墙 | ✅ `LightOccluder2D` 真遮挡（墙后/底噪 0.99×） |
| 灯的形状 | 屏幕正圆（地面被拉成椭圆） | 地面正圆（贴图纵向压 0.62） |
| 墙脚受光 | 无此概念 | 削底 16px，墙脚有受光带 |

**⚠️ 内容上 Godot 线已经跑到前面了**

原先的约定是「跨版本改玩法时，以 Web `src/game/*.ts` 为准，Godot 版照抄」。
从这一轮起这条**不再成立**，下面这些在 Web 版里**没有对应实现**，Godot 版是唯一实现：

- 8 把武器 / 19 个技能（Web 版是 3 把武器）
- 14 个恩赐 + 三选一肉鸽循环
- 5 个精英词缀、种子随机的波次编排
- 第二关「无芯之暗」：火盆与不死再生、盲女同行、分阶段 Boss
- 敌人 `扑灯蛾 moth`

所以：**下次要动这些内容，得先决定以哪边为准**，别默认"Web 是权威"。
反过来，Web 版仍是一到三关数值调平的参考 —— 那边有商店/升级/存档，Godot 版还没有。

**刻意保留的差异（有理由）**

1. **玩家脚下的烘焙光池半径从 `0.55×` / `0.30×` 收成 `0.26×` / `0.15×`**。
   Web 版把这圈当成「唯一的光」所以开得很大；但它是 `_draw` 画的、**不认遮挡**，
   一大团暖光会直接糊在墙后的阴影上，正好抵消 `LightOccluder2D` 的意义。
   现在只留贴着脚的一小圈暖芯，真正的照明交给会被墙挡住的那盏 `PointLight2D`。

**移植过程中补齐的、Web 版本来就有而初版漏掉的行为**

2. **Boss 的贴身接触伤害**（Web `world.ts` 的 `d < e.r + p.r + 6` 那条）。
   漏了它的症状很直观：站在 Boss 身边完全不掉血，Boss 失去压迫感。
3. **敌人移动的恒定阻尼与撞墙反弹**。Web 版 `moveEntity()` 每帧对速度做
   `damp(v, 0, 2.6, dt)`，外加撞墙 `v *= -0.2`——这一条是**敌人实际速度的真实来源**，
   阻尼后约为标称速度的 0.69 倍。不补的话敌人在 Godot 版里会快 45%。
   还有一条：Boss 冲撞撞墙要眩晕 1.1s。
4. **敌人互相分离**（Web `updateEnemies()` 里的互推），避免叠成一团。
5. **敌人近战攻击的结算方式**：改为「前摇结束当帧结算 + 前冲冲量（guard 240 / 其他 150）
   + 挥击特效」，与 Web 版一致。
6. **对白翻页键**补上 `E`/`F`（Web 版用 `Space`/`E`/`F`/`Enter`）。

### 11. 修回三条会"静默失败"的 bug（全屏闪光残留 ×2 + 三选一徽记错位）

这三条来自一次外部 PR（`maxlen727` 的 `fix/godot-fx-residual`，提交 `55cb837`）。
那个 PR 曾被合并，后来因为要先保住本地工作被强推退掉了，所以**这三条是我们自己重新实现的**
（不是 cherry-pick；基线已经被宝箱/背包/守灯人那轮改过，直接套用会错位）。
`git fetch origin refs/pull/1/head` 随时能把原提交取回来对照。

三条的共同点是**都不会报错、也不会让断言变红，只是画面上悄悄不对**：

| # | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 换关卡 / 重生后，上一关死亡的**红闪一直盖在新画面上** | `flash_rect` 挂在**常驻 HUD** 上，而 `flash_power` 是 **World 实例**成员。`hud.refresh()` 只在 `power > 0` 时写颜色，新世界从 0 开始，那个分支**永远不再走** | `refresh()` 补 `else: flash_rect.color = Color(0,0,0,0)` |
| 2 | 死亡红闪**卡在结算画面上**不动 | 闪光衰减原本写在 `world.step()` 里，而对白 / 菜单 / 三选一 / 商店期间世界被冻结（`advance()` 不调 `step()`） | 抽成 `World.tick_fx(dt)`，由 `main.advance()` **无条件**调用 |
| 3 | **多张恩赐卡长得一模一样**（徽记回退默认图） | `Hud.EMBLEMS` 的键还是老版本恩赐 id（`bright`/`fuel`/`kindle`/`greed`/`heavy`/`dr`/…），与 `content.gd` 现在的 id 完全对不上 | 按 `content.gd` 的 `WEAPONS`/`BOONS`/`WEAPON_AFFIXES` 重写 |

`tick_fx` **不消耗任何 RNG**，所以"世界冻结期间也推进表现层"不会挪动随机流 ——
确定性自检（连跑两遍逐字节相同）不受影响。

#### 一个意外的收获：原来的遮挡断言是**擦着阈值过**的

修完 bug 2 之后，遮挡那一段的数字全变了。原因不是光被改坏，而是**原来的采样被污染了**：

`set_post_enabled(false)` 只关**暗角**层，**管不到 `flash_rect`**（它就是一块全屏 `ColorRect`）。
而遮挡那一段正好会连续弹几段对白把世界冻住 —— 旧的衰减写在 `step()` 里、对白期间不跑，
于是**一发残留的闪光一直糊在采样区上**，给每个采样点加了个近似常数，把"墙后 vs 底噪"的比值压平：

| 断言 | 修复前 | 修复后 |
| --- | --- | --- |
| 墙前 / 射程外 ≥ 3× | 16.3× | **48.5×** |
| ★ 关阴影时墙后 > 射程外 ×2 | **2.04×**（险过） | **5.25×** |
| ★ 开阴影时墙后 ≈ 底噪（≤ 1.15×） | **0.99×**（几乎必然通过） | **0.61×** |
| 墙后降幅 | 75.8% | **94.2%** |

也就是说，这两条"核心结论"断言原来是在**逼近一个被污染的比值**上勉强成立的。
顺手记一条规则：**任何全屏叠加层只要不在 `set_post_enabled` 的管辖内，就必须在采样前
显式确认它是透明的** —— 否则像素断言测的是叠加层，不是光。

#### 这段的断言（8 条，每一条都能单独失败）

徽记 3 条（在 `_section_assets`）：
1. `EMBLEMS` 覆盖**全部**武器 / 恩赐 / 词条 id（不靠 `star_06` 兜底）
2. `EMBLEMS` 的每个值都能被 `Art.tex()` 解析成**真实贴图**（写错一个字母不会报错，徽记会直接隐形——比回退更糟）
3. 卡片可见 id 的贴图**有区分度**（同一张最多被 2 个 id 复用），防"十张卡一个样"退化

闪光 5 条（在 `_section_drops_death`）：
4. 死亡瞬间红闪**确实亮在屏幕上**（给后面几条制造真实前提，否则"清掉了"是同义反复）
5. 死亡期间（世界冻结）闪光照常**淡出**，且 `flash_rect.color.a` 归零
6. 结算期间**世界时间没有前进**（证明世界真的停住了——少了这条，第 5 条在"衰减其实写在 `step()` 里"的实现下也能过）
7. 重生**前**手动再点亮一次红闪并确认它在屏幕上（否则第 8 条又是同义反复）
8. 重生后全屏滤镜**已清除**（真正在盯 `refresh()` 的 `else` 分支）

第 6、7 条是刻意的"防同义反复"设计：**先断言前提成立，再断言结论**。

六、踩坑记录
--------------------------------------------------------------------

### Godot 4 相关

1. **GDScript 从 `Array`/`Dictionary` 取值不能直接用 `:=` 推断**。
   `var h := w[4]` 是 Variant，编译器会直接报
   `Cannot infer the type of "h" variable`。要么 `float(w[4])`，要么显式声明类型。
   从 `Array` 里 `for` 出来的循环变量同理（`for side in [-1.0,1.0]` 里的 `side`
   也不能 `:=` 出 `float`）。
2. **`just()` 语义要求「按下—松开」**。自检的 `_tap()` 一开始只置位、不归位，
   于是连续两次 `_tap` 之间不会形成第二次边沿，对白永远卡在第一句。
   → `_tap` 必须"按下走一步、松开再走一步"。
3. **GDScript 协程在第一个 `await` 处就让出控制权**。`_run()` 里漏掉
   `await _check_boot()`，后面的段落就和它**并发**推进了——断言前提错位、
   截图拍成"别人已经改过的世界"。发现它的铁证是两张本该完全不同的截图
   **字节完全相同**。
4. **对白期间世界是冻结的**（`advance()` 在 `state == "dialogue"` 时不调 `world.step()`，
   与 Web 版行为一致）。所以 Boss 出场那段过场对白不点完，后面 `_pump(240)`
   一步都不会推进——"Boss 会攻击玩家"必然测不到。
5. **叠加层必须显式标脏**。`Bloom` 是独立的 `CanvasItem`，`World.step()` 里只对自己
   `queue_redraw()`，于是那层加法混合（玩家地面光池、灯芯辉光、挥击亮芯）
   **冻结在最后一次重绘的瞬间**。症状：玩家脚下的光池不跟着人走、半径也不变。
6. **断言别写「离墙还有 20px」这种想当然的阈值**。碰撞解算会把玩家正好顶在墙面上，
   稳态间隙就等于玩家半径；正确判据是「圆心 + 半径不超过墙面」。
7. 本机 `/tmp` 是 10MB 的 tmpfs，Godot 的 `TMPDIR` 必须指到真实磁盘，
   否则进程会莫名其妙崩。一键脚本里已经处理。

### 自检怎么写才不会骗自己（这一轮新踩的，代价都不小）

8. **参与仿真的随机数必须来自种子，不能用全局 `randf()`**。
   `EnemyState.create()` 里 `wob = randf() * TAU`，`wob` 是敌人绕行的相位，
   而它直接进 `vx/vy` —— 于是每趟跑出来的世界都不同，
   「连跑两遍逐字节相同」这条就废了。改成按 id 铺开黄金角
   （`fmod(float(eid) * 2.39996323, TAU)`）：彼此不同、分布均匀、完全可复现。
   **排查线索**：只有依赖玩家行为的那几段（机器人试玩）对不上，纯逻辑断言全绿。
9. **会冻结世界的界面不止一种，`_pump` 必须把两种都点掉**。
   `dialogue` 和肉鸽的 `draft` 都不调 `world.step()`。少点一种，
   后面所有段落会**成片**变红，症状是一大堆看似无关的断言同时失败
   （敌人不动、镜头不跟、盲女不跟人走、灯不亮…）。
   `_pump(n, hold, auto_draft, auto_dialogue)` 默认两种都自己处理；
   专门要验它们的那几段（"面板真的弹出来了""过场对白点得完"）把对应的 `auto_*` 关掉。
10. **"对比前 vs 对比后"必须把其他变量全冻住**。
    「盲女在身边更亮」这条最初测出 `248 -> 248`（差 0）。原因不是逻辑错，
    而是**基准值本身就含了那 +52** —— 玩家已经在盲女身边站了 8 秒。
    而且光照半径里还有 `combo`、`glow`（挥击辉光）两个会变的项，
    其中 `glow` 一旦被写成 1.0 就**不再衰减**（只有 Boss 倒下时才被写成 1.0）。
    → 正确做法：把 combo/glow 归零、保证无敌、只改盲女的位置，
    相邻两步各测一次。现在断言是"差**恰好** 52"（允许 0.5 误差），比"大于"强得多。
11. **多走一步都会挪动 RNG 流**。为了加一张截图而多推 6 步，
    结果撞掉了几十条断言之后的「链锁把敌人拽近」。固定步长 + 全局单流 RNG 下，
    步数就是"货币"。要么别多走，要么**补回来**
    （`_pump(6)` + 截图 + `_pump(74)`，总数仍是原来的 80）。
12. **分阶段的东西要按阶段验**。Boss 的 `beam` 分阶段才有：
    phase 1 的招式池里根本没有 `drain/sweep`，满血 Boss 打死也放不出光束。
    第一次写这条断言时它一直失败，查了半天才发现不是特效坏了，是**阶段没到**。
13. **"收集到的东西"要有断言消费它，否则是死代码**。
    这一段从 `_collect_kinds` 采集特效种类的逻辑写好之后，断言那行在改动中丢了，
    变成"采集了但没人看" —— 表面上 129/129 全绿，实际上"特效真的不同"这条**根本没在验**。
    补回来后立刻抓到 `beam` 的真实归属问题（见 12）。
