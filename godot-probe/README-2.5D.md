# 2.5D 俯视下，遮挡体（Occluder）该贴在哪一块

> 这是 [README.md](./README.md)（第一探针）的续篇。第一探针回答的是「Godot 的 2D 光会不会被墙挡住」，答案是会。
> 但那个结论是在**纯正面视角**下拿到的：墙 = 屏幕上一个矩形，遮挡体与它重合即可。
> 本项目用的是 **2.5D 俯视**，墙在屏幕上由两块语义不同的面拼成，于是「遮挡体贴哪一块」成了一个新问题。
> 本文件是这最后一个未知数的实测结论。

复现：`tools/godot-probe25d.sh`（22 个用例，真实 Godot 渲染，断言不通过则非零退出）

---

## 0. 一句话结论

**遮挡体贴「你在屏幕上画出来的那块整体轮廓」，并且只把它的底边削掉约 16px。**

不要贴「地面足迹」，也不要对轮廓做四边均匀内缩。

```gdscript
# 以 render.ts 的 drawWall 变量名为准：
#   yN = 足迹北沿屏幕 y， yS = 足迹南沿屏幕 y， h = 立起来的高度
var silhouette := Rect2(x0, yN - h,  x1 - x0,  (yS - yN) + h)      # ← 画出来的那块
var occluder   := Rect2(x0, yN - h,  x1 - x0,  (yS - yN) + h - 16) # ← 只削底边 16px，推荐
# 不要用 Rect2(x0, yN, x1 - x0, yS - yN)          —— 那是地面足迹
# 也不要用 silhouette.grow(-16)                    —— 四边均匀内缩会从墙顶漏光
```

顺带一条：`drawWall` 里那道 8px 的东侧厚边（`rgba(0,0,0,0.55)` 的侧面）**不要**并进遮挡体——它是个侧面，让它可以受光反而是对的。

## 1. 为什么 2.5D 会冒出这个问题

投影是 `屏幕 y = 世界 y × 0.62`（与 `render.ts` 的 `YSQUASH` 一致），墙从地面足迹向屏幕上方立起 `h`。
于是屏幕上一堵墙由两块拼成（与 `drawWall` 逐行对应）：

```
                      ┌──────────────┐  ← yN - h
                      │    顶  面     │     足迹整体上移 h 的那块矩形（代表墙顶）
   yN ────────────────├──────────────┤  ← 顶面/立面的分界（对细墙是 313.6）
                      │   南 立 面    │     从足迹南沿向上立起 h（代表朝镜头那面墙）
   yS ────────────────┴──────────────┘  ← 墙脚
                      ↑ 这两块合起来 = 屏幕上看到的「墙」
```

而**地面足迹**（真正占着地板的那块）只是这个轮廓里偏下的一条横带：

| 墙型 | 世界尺寸 w×d×h | 屏幕足迹 | 屏幕轮廓 | 足迹占轮廓 |
|---|---|---|---|---|
| fence（细墙，最常见） | 200×60×46 | 200×37.2 | 200×83.2 | 45% |
| pillar（窄柱） | 60×60×46 | 60×37.2 | 60×83.2 | 45% |
| block（厚块，如灯塔基座） | 140×400×54 | 140×248.0 | 140×302.0 | 82% |
| tall（高墙，假定） | 200×60×150 | 200×37.2 | 200×187.2 | 20% |

尺寸全部照抄 `src/game/levels.ts` 里真实存在的墙。

灯的规格：屏幕半径约 440px、`energy` 1.15。这对应游戏内玩家灯圈的**上限档**
（`radius = 150 + min(combo,40)×7 = 430`，`energy 1.15`，见 `world.ts:409` 与 `render.ts:881`）。
刻意取偏亮的一档，好让「翻过墙顶」的漏光在采样点上仍然可辨。

四个光照方向各测一次：灯分别站在墙的**正面（南）、背面（北）、西侧、东侧**，离墙 90px（侧面）/120px（正背面）。

## 2. 四种摆法的实测对照

**侧光**（灯在墙西侧、与足迹同高——最刁钻的方向），亮度为采样区平均值，未受光地板底噪 ≈ 0.048：

| 遮挡体 | 墙前地面 | **墙后地面** | 墙面顶面 | 墙面暗带 | 墙脚受光高度 |
|---|---|---|---|---|---|
| 地面足迹 | 0.8083 | **0.4834** ⚠️ 光翻过去了 | 0.2222 ⚠️ 墙身被照亮 | 0.0199 暗带 | 0 |
| 整体轮廓 | 0.8083 | **0.0482** ✅ | 0.0255 ✅ 剪影 | 0.0199 | 0 |
| 轮廓 + 削底 16px | 0.8083 | **0.0482** ✅ | 0.0255 ✅ | 0.0825 墙脚亮 | **13px** ✅ |
| 轮廓 + 四边内缩 16px | 0.8083 | **0.3153** ⚠️ 从墙顶漏 | 0.0255 | 0.0861 | 14px |

**正面光**（玩家站在墙前面，最常见）：

| 遮挡体 | 墙前地面 | 墙后地面 | 墙脚受光高度 |
|---|---|---|---|
| 地面足迹 | 0.6894 | 0.0482 | 0 |
| 整体轮廓 | 0.6894 | 0.0482 | 0 |
| 轮廓 + 削底 16px | 0.6894 | 0.0482 | **15px** |

**背光**（灯在墙后）：

| 遮挡体 | 墙面 | 墙后地面（灯这侧） | 墙前地面 |
|---|---|---|---|
| 地面足迹 | 0.3240 ⚠️ 墙面反被照亮 | 0.6930 | 0.0482 |
| 轮廓 + 削底 16px | 0.0255 ✅ 剪影 | 0.6930 | 0.0482 |

## 3. 八条发现，其中三条和我预判相反

### ① 脚印模型的漏光点不在侧面，在**墙顶上方**（预判反了）

我原本以为漏光会出现在"墙的侧面"——实测侧面是 **0.0482**（全黑，没漏）。
漏的是**墙后地面：0.4834，比轮廓模型的 0.0482 亮 10 倍**。

原因很干净：灯与足迹同高，**水平方向的光线必然穿过足迹被挡住**；只有向上的光线能"翻过"足迹的上沿，
而足迹的上沿在屏幕上只有 37px 高，墙后面的地面却在那之上 34px 处——正好落在翻过去的光里。

### ② "墙越窄漏得越厉害"是错的，**宽墙才需要轮廓模型**

| 墙型 | 脚印模型·墙后 | 轮廓模型·墙后 |
|---|---|---|
| 细墙 200px 宽 | 0.4834 | 0.0482（10× 差） |
| 厚块 140×400 | 0.1702 | 0.0482（3.5× 差） |
| 窄柱 60px 宽 | 0.5984 | 0.4169（都亮） |

窄柱两种模型都亮，因为**光本来就绕得过去**——那 60px 宽的柱子对灯的张角只有 34°，绕过去的部分是真能到墙后的。
真正需要轮廓模型的是**光绕不过去**的场合：宽墙、厚块。

### ③ 第一探针的"均匀内缩"规则**不能直接搬到 2.5D**

第一探针的结论是「遮挡体四边均匀内缩 N 像素 → 墙面受光深度 = N」。
在 2.5D 里这条会踩雷：**轮廓的上沿就是墙顶轮廓**，四边均匀内缩等于把墙顶也削掉一截，
侧光便从墙顶漏进去——墙后地面 0.3153，比不内缩的 0.0482 亮 6.5 倍。

**只削底边**才不会漏（0.0482），因为底边是墙脚，削它只会让光多照到墙脚。

### ④ 削底边是唯一"无副作用"的照亮墙脚方式，而它有个刻度

| 削底量 | 正面光下墙脚受光 | 侧光下墙脚受光 | 底座溢光（光从墙脚溢到另一侧） |
|---|---|---|---|
| 0 | 0 | 0 | 0.0482（无） |
| 8px | 7px | **0.33px**（等于没有）⚠️ | 0.0482（无） |
| 16px | 15px | 13px | 0.1058（≈ 墙前 0.8083 的 13%） |

削 8px 在**侧光下完全亮不起来**：灯在足迹中高处，光线要到墙脚必须斜向下，正好穿过遮挡体的下半身。
想让墙脚在任意方向都受光，削底量要 ≥ 16px；代价是墙脚的光会从底座溢到墙的另一侧约 13% 亮度。
这是个**美术旋钮**：削多少 = 墙脚亮多高，实测关系是 `受光高度 ≈ 削底量 − 1~3px`。

### ⑤ 背光时脚印模型会把墙面照亮：0.3240 vs 剪影 0.0255（12.7×）

玩家站在墙北侧，看到的是墙的**南立面**——却被身后的光照亮了。轮廓模型下墙永远是剪影。

### ⑥ 正面光下两种模型**完全无法区分**

`S_fence_foot` 与 `S_fence_sil` 的全部 9 个采样点数值**一模一样**。
所以这个决策只影响侧光与背光。正面是最常见的场景，也因此这个坑很晚才暴露。

### ⑦ 厚块的墙脚在侧光下亮不起来是**几何必然，不是缺陷**

厚块足迹深 248px，灯站在足迹中部（比墙脚高出 124px），到南沿的射线必然穿过遮挡体下半身。
正面光下正常（16px 受光）。这条已从断言里拆出来单独记录。

### ⑧ 2.5D 的灯**必须竖压成椭圆**——而且这条现在就可以在 Web 版先修掉

在**同一个地面距离**上取样（东向 300px、北向 300×0.62=186px，即地面上等距的两点）：

| 灯的贴图 | 北/东亮度比 | 含义 |
|---|---|---|
| 屏幕正圆 | **1.6968** | 纵向多照 70%（屏幕上圆，投到地板上是长椭圆） |
| 竖压椭圆（= 地面正圆） | **1.007** | 各向等距 ✅ |

**Web 版现在用的是屏幕正圆**（`render.ts` 的 `applyLighting` 里 `createRadialGradient` 直接按屏幕像素画圆），
也就是说"连击提高亮度"这个数值在地面上是**各向异性**的：南北方向的实际照到距离比东西方向多 60%。
这条与换不换引擎无关，可以直接先在 Web 版改掉（把光斑纵向缩到 0.62 即可）。

## 4. 为什么最终选"轮廓"而不是"足迹"

两种摆法各自内部都自洽，区别在于**你把墙的哪一面认成"墙"**——2.5D 的假高度轴注定只能选一个：

| | 贴地面足迹 | 贴整体轮廓 |
|---|---|---|
| 地面阴影 | 与足英尺完全一致（更"物理正确"） | 比足迹长，多出的部分落在被墙自己挡住的地板上 |
| 墙身明暗 | **顶面被照亮**（0.22），立面被足迹的影子横切出一条暗带 | 整块剪影，只有墙脚被削出的一条亮边 |
| 侧光 | 光从墙顶翻到墙后 | 墙后全黑，阴影按墙顶轮廓投出 |
| 背光 | 墙面被身后的光照亮（X 光感） | 剪影 |
| 观感 | 像一堵**矮墙/台沿**，光漫过去了 | 像一堵**不透光的墙** |

灯骑士的墙是城堡外墙、建筑基座，玩家心里那堵墙是不透光的；而且游戏的核心观感就是"黑暗里的一盏小灯"——
**轮廓模型给的是"墙=实心障碍"这个直觉**，代价只是阴影比足迹长一点。

> 如果你更想要"矮墙可以被光漫过"的效果（比如篱笆、门槛），那就用足迹——但要接受墙顶发亮的观感。
> 想两者兼得，得往 3D 走（真高度轴），或者按面拆开：Godot 支持给 `CanvasItem` 单独设 `light_mask`，
> 可以把顶面排除在玩家灯光之外、只让立面吃光——那是另一套做法，本探针没测。

## 5. 已知限制（这条结论没覆盖什么）

1. **墙在屏幕上是轴对齐矩形**。斜置的墙、L 形、圆形遮挡体没测；不过结论是"贴你画的那块"，对任意多边形应同样成立。
2. **只测了 4 个离散光照方向**，没做角度扫描。侧面（W/E）是最刁钻的那档，已被覆盖；45° 斜角没单独测。
3. **灯被放在地面（玩家脚底）**，与 `render.ts:881` 的 `addLight(p.x, p.y, ...)` 一致。
   如果把灯建模成"提在手上的灯笼"（抬高一截），物理上正确的遮挡体会落在"足迹"与"轮廓"之间。
   本探针没有引入这个高度变量——它会让结论多一维，而两种极端都测了，取哪一端是美术决定。
4. **像素级数值依赖软件渲染**。本机没有独显，跑的是 llvmpipe；真显卡上数值会有差异，
   但上面所有**结论性判断**（谁比谁亮、谁的墙后是黑的）不受影响。
5. 阴影边缘做了锐化（`shadow_filter_smooth = 0`）以便采样；实际项目里要开 PCF 柔化，边界数值会变，方向不变。

## 6. 迁移到 Godot 时的落地清单

1. 每堵墙画两块 `Polygon2D`：顶面（足迹上移 h）+ 南立面（足迹南沿向上立起 h）——与 `drawWall` 的几何逐像素一致。
2. 给这堵墙加**一个** `LightOccluder2D`，多边形 = 上面那个 `occluder` 矩形（轮廓削底 16px），
   挂在墙节点下、用屏幕坐标（`OccluderPolygon2D.closed = true`）。
3. 玩家灯光：`PointLight2D`，`texture` 用**纵向压到 0.62 的椭圆**贴图，`shadow_enabled = true`。
   亮度 `energy` 与半径直接映射 `world.ts` 的 `lightRadius` / 连击曲线。
4. 全屏压暗用 `CanvasModulate`（注意它压不暗视口的清屏色——地板必须显式画一块接光，见第一探针 README）。
5. 墙的"黑暗中可辨"可以继续用现在那招：给墙自身挂一盏极弱的自发光灯（`render.ts:332` 的 `0.1` 强度），
   这样剪影模型下墙的轮廓不会糊成一片。
